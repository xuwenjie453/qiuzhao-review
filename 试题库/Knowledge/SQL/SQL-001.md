### SQL-001-001 | ★★★★☆

写一个每部门工资前三名的查询（窗口函数）

**答案：**
```sql
SELECT dept, name, salary
FROM (
  SELECT dept, name, salary,
         DENSE_RANK() OVER (PARTITION BY dept ORDER BY salary DESC) AS rk
  FROM emp
) t
WHERE rk <= 3;
```

要点：`ROW_NUMBER` 给唯一序号（并列也分先后）、`DENSE_RANK` 并列同名次不留空位（1,1,2）、`RANK` 并列同名次跳号（1,1,3）。"前 N 名含并列"用 DENSE_RANK，"只要三条记录"用 ROW_NUMBER——面试官常靠这个辨析深浅。MySQL 8.0 起支持窗口函数；5.7 需用相关子查询模拟（`count(distinct salary) > 自己的` 计数法）。


### SQL-001-002 | ★★★★☆

JOIN 的几种类型与执行语义？

**答案：**
INNER JOIN 只保留两表连接键匹配的行；LEFT JOIN 保留左表全部行，右表无匹配补 NULL；RIGHT JOIN 镜像；FULL OUTER JOIN 双向保留（MySQL 不支持，用 LEFT+RIGHT UNION 模拟）。高频陷阱：①LEFT JOIN 后在 **WHERE** 里写右表过滤条件 `r.col = x`，会把无匹配行（NULL）过滤掉，等效变成 INNER JOIN——过滤右表条件应写在 **ON** 里；②连接键 collation/类型不一致导致索引失效（K-MYSQL-014）；③大表 JOIN 要小表驱动大表、被驱动表连接键有索引。


### SQL-001-003 | ★★★★☆

GROUP BY 与聚合的语义规则？

**答案：**
规则一句话：**SELECT 中出现的非聚合列必须全部出现在 GROUP BY 中**（MySQL 开启 only_full_group_by 后强制；关闭时取"该组第一行"的任意值，是数据事故来源）。WHERE 在聚合前过滤行，HAVING 在聚合后过滤组；聚合函数忽略 NULL（COUNT(col) 不数 NULL，COUNT(*) 数行，K-MYSQL-015）。常用扩展：GROUP_CONCAT 把组内值拼接、WITH ROLLUP 生成小计。


### SQL-001-004 | ★★★★☆

NULL 在 SQL 中的特殊语义？

**答案：**
NULL 表示"未知"而非"空值/0"，三值逻辑（TRUE/FALSE/UNKNOWN）：与 NULL 的任何比较（=、<>、>）结果都是 UNKNOWN，而 WHERE 只保留 TRUE——所以 `where col <> 'x'` 会**漏掉 col 为 NULL 的行**（这是最高频的 SQL 逻辑 bug）。判断必须用 IS NULL / IS NOT NULL。延伸：COUNT(col) 忽略 NULL、NOT IN 子查询含 NULL 时整条返回空（UNKNOWN 传播）、聚合函数忽略 NULL、唯一索引允许多个 NULL（MySQL）。


### SQL-001-005 | ★★★★☆

LEFT JOIN 过滤位置

现有部门表 `dept(dept, city)`：('A','北京'), ('C','上海')。执行：

```sql
SELECT e.name, d.city
FROM emp e LEFT JOIN dept d ON e.dept = d.dept
WHERE d.city = '上海';
```

结果包含几行？

A. 1 行（'戊'）
B. 3 行（A 组三人，city 为 NULL 被过滤剩 C 组）
C. 5 行
D. 2 行

**答案：** A

**解析：**
- A：正确。LEFT JOIN 先保留 emp 全部 5 行（B 部门员工 city 为 NULL）；WHERE d.city='上海' 过滤掉所有非 C 部门行（含 NULL），只剩 '戊' 一行——LEFT JOIN 实际退化为 INNER JOIN 效果。
- B：错误。city 为 NULL 的行不满足 ='上海'，会被过滤。
- C：错误。WHERE 过滤后不是全表。
- D：错误。无此口径。

OUTER JOIN 的右表条件写 WHERE 会退化为 INNER JOIN；应写 ON。


### SQL-001-006 | ★★★★☆

GROUP BY + COUNT(col)

执行 `SELECT dept, COUNT(*) AS c1, COUNT(bonus) AS c2, SUM(bonus) AS s FROM emp GROUP BY dept;` 关于 B 部门的行，正确的是：

A. c1=2, c2=2, s=20
B. c1=2, c2=1, s=20
C. c1=2, c2=1, s=NULL
D. c1=1, c2=1, s=20

**答案：** B

**解析：**
- A：错误。COUNT(bonus) 忽略 NULL，丁的 bonus 为 NULL 不计入，c2=1。
- B：正确。B 部门两行（丙、丁）：COUNT(*)=2；bonus 中只有丙的 20 非 NULL，COUNT(bonus)=1；SUM(bonus)=20。
- C：错误。SUM 忽略 NULL 后对非 NULL 值求和，组内存在非 NULL 值时结果为 20 而非 NULL（组内全 NULL 时 SUM 才是 NULL）。
- D：错误。GROUP BY 后 B 是一组两行。

COUNT(col)/SUM 忽略 NULL；COUNT(*) 计行数。


### SQL-001-007 | ★★★★☆

NOT IN 与 NULL

部门表 `dept(dept, city)` 数据：('A','北京')、('B',NULL)、('C','上海')（B 部门城市未知）。执行：

```sql
SELECT name FROM emp
WHERE dept NOT IN (SELECT dept FROM dept WHERE city <> '上海');
```

子查询选出非上海部门（注意：B 部门 city 为 NULL，`city <> '上海'` 对其求值为 UNKNOWN，该行被过滤，故子查询实际只返回 ('A')）。该查询返回：

A. 2 行（B 部门的乙、丁）
B. 0 行
C. 3 行（甲、乙之外的全部）
D. 5 行

**答案：** B

**解析：**
- A：错误。这是忽略 NULL 的直觉答案。子查询实际返回 ('A', NULL)，`dept NOT IN ('A', NULL)` 中任何非 A 的值与 NULL 比较为 UNKNOWN，整个条件不为 TRUE，无行返回。
- B：正确。三值逻辑：`x NOT IN (a, NULL)` ≡ `x<>a AND x<>NULL`，后者恒为 UNKNOWN（当 x≠a），WHERE 只保留 TRUE，因此整体返回空集。
- C：错误。行数不成立，且 A 部门行应被排除。
- D：错误。NOT IN 有过滤语义，不会全保留。

NOT IN 子查询含 NULL → 整体返回空集；安全写法：`NOT EXISTS (…)` 或子查询内排除 NULL。


### SQL-001-008 | ★★★★☆

窗口函数与 GROUP BY

执行：

```sql
SELECT name, salary,
       RANK() OVER (ORDER BY salary DESC) rk
FROM emp;
```

工资 150 的两位员工（丙、丁）得到的 rk 是：

A. 都是 2
B. 2 和 3
C. 都是 3
D. 1 和 2

**答案：** C

**解析：**
- A：错误。"并列同名次"是 DENSE_RANK 的行为。
- B：错误。RANK 并列时两人同名次，不会分出 2 和 3。
- C：正确。全表降序序列：300(戊) rk=1，200(乙) rk=2，150(丙、丁) 并列 rk=3，100(甲) 跳号 rk=5。
- D：错误。"并列强行分先后"是 ROW_NUMBER 的行为。

RANK 并列同号跳号（1,2,3,3,5）；DENSE_RANK 并列同号不跳（1,2,3,3,4）；ROW_NUMBER 强制唯一（1,2,3,4,5）。


### SQL-001-009 | ★★★☆☆

CASE 表达式统计

表 order(id, status, amount)，status ∈ {'PAID','REFUND','PENDING'}。统计各状态金额合计且仅统计已支付与已退款，正确语句是：

A. `SELECT status, SUM(amount) FROM o WHERE status IN ('PAID','REFUND') GROUP BY status;`
B. `SELECT SUM(amount) FROM o GROUP BY status HAVING status='PAID';`
C. `SELECT status, amount FROM o WHERE status<>'PENDING';`
D. `SELECT COUNT(status), SUM(amount) FROM o;`

**答案：** A

**解析：**
A 先过滤再分组求和，正确；B 只能得一个状态；C 没聚合；D 统计了全部状态且无分组。

WHERE 过滤行（聚合前），HAVING 过滤组（聚合后）。


### SQL-001-010 | ★★★☆☆

窗口函数与 GROUP BY 并用

`SELECT dept, SUM(salary) AS total, RANK() OVER (ORDER BY SUM(salary) DESC) AS rk FROM emp GROUP BY dept;` 关于该语句，正确的是：

A. 语法错误，窗口函数不能与 GROUP BY 同用
B. 合法：GROUP BY 先聚合，窗口函数作用于聚合后的每行
C. rk 全为 1
D. 返回行数多于部门数

**答案：** B

**解析：**
窗口函数在 GROUP BY 聚合之后执行，可对聚合结果排序打名次；A 错；C 错（除非只有一组）；D 错（行数=部门数）。

SQL 逻辑执行顺序：FROM→WHERE→GROUP BY→HAVING→SELECT（含窗口）→ORDER BY。


### SQL-001-011 | ★★★☆☆

EXISTS 与 IN 选择

子查询表 B 远大于外表 A 时，`WHERE id IN (SELECT id FROM B)` 与 `WHERE EXISTS (SELECT 1 FROM B WHERE B.id=A.id)` 通常更优的是：

A. IN 更优
B. EXISTS 更优
C. 完全等价
D. 取决于月亮

**答案：** A

**解析：**
小外表+大子表时，IN 让优化器把小表作驱动、大表走索引半连接，通常更优；EXISTS 按外表逐行探测子查询，外表小同样可行，但经验规则"小表驱动"下 IN 占优；B 是"外表大子表小"时的经验答案；C 忽略了执行计划差异。

经验法则：外表大用 EXISTS、子表大用 IN；最终以执行计划为准。
