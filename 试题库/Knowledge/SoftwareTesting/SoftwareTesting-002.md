### SoftwareTesting-002-001 | ★★★☆☆

你印象最深刻的 bug 是什么？

**答案：**
开放性项目经历题，没有标准答案。建议按STAR结构讲一个真实bug：现象、定位过程（日志/断点/二分法缩小范围）、根因、修复与回归验证，并总结从中沉淀的通用排查方法。


### SoftwareTesting-002-002 | ★★★☆☆

黑盒测试的方法有哪些？

**答案：**
等价类划分、边界值分析、判定表、因果图、场景法、错误推测法、正交实验法。


### SoftwareTesting-002-003 | ★★★☆☆

测试用例怎么编写与设计？

**答案：**
依据需求文档进行需求分析，运用等价类/边界值/判定表/场景法等方法设计，覆盖功能、异常、边界、兼容、安全等维度，并组织评审。


### SoftwareTesting-002-004 | ★★★☆☆

测试用例都包含哪些要素？

**答案：**
用例编号、所属模块、标题、优先级、前置条件、测试步骤、测试数据、预期结果、实际结果等。


### SoftwareTesting-002-005 | ★★★☆☆

测试排期应该怎么估算？

**答案：**
按模块拆解用例设计/执行/回归工作量，结合复杂度加权、历史数据与人员并行度估算，并预留bug修复回归缓冲。


### SoftwareTesting-002-006 | ★★★☆☆

如何判断一个功能能否进行自动化测试？

**答案：**
看功能是否稳定、是否需要频繁回归、操作是否可重复、界面是否频繁变动、投入产出比（ROI）。


### SoftwareTesting-002-007 | ★★★☆☆

Selenium 自动化中如何定位一个动态的元素（id/class 动态变化）？

**答案：**
避开动态属性，用稳定的静态属性、文本、相对位置（xpath轴）、contains匹配局部特征定位。


### SoftwareTesting-002-008 | ★★★☆☆

Selenium 框架的运行原理是什么？

**答案：**
Client端代码通过WebDriver协议（W3C标准，HTTP+JSON）向浏览器驱动（chromedriver等）发送命令，驱动解析后操作浏览器，并返回执行结果。


### SoftwareTesting-002-009 | ★★★☆☆

Selenium 定位元素的方法都有哪些？

**答案：**
id、name、class name、tag name、link text、partial link text、xpath、css selector 八种。


### SoftwareTesting-002-010 | ★★★☆☆

Appium 用过吗？原理是什么？

**答案：**
C/S架构，Appium Server接收客户端（测试脚本）请求，通过各平台的驱动（UIAutomator/XCUITest）在设备上执行，实现跨平台移动自动化。


### SoftwareTesting-002-011 | ★★★☆☆

fiddler 怎么抓取 https 请求？

**答案：**
开启HTTPS解密选项，安装并信任Fiddler根证书；移动端需在wifi代理指向Fiddler并安装证书（高版本Android需将证书装为系统证书）。


### SoftwareTesting-002-012 | ★★★☆☆

性能测试如何做的？说说完整流程。

**答案：**
明确压测目标与指标→设计场景（单接口/混合/稳定性）→准备数据与环境→开发压测脚本（JMeter等，参数化、关联、断言）→执行压测→监控（服务器/CPU内存/DB）→分析瓶颈与调优→输出报告。


### SoftwareTesting-002-013 | ★★★☆☆

性能测试需要关注哪些方面（指标）？

**答案：**
TPS/QPS、响应时间（平均、90/95/99分位）、并发数、错误率、资源利用率（CPU、内存、IO、网络、带宽）。


### SoftwareTesting-002-014 | ★★★☆☆

QPS 和 TPS 的区别是什么？

**答案：**
QPS每秒查询/请求数（面向单次请求），TPS每秒事务数（一个事务可含多个请求/操作），一个事务可能对应多个QPS。


### SoftwareTesting-002-015 | ★★★☆☆

最大连接数和 QPS 的区别是什么？

**答案：**
最大连接数是系统同时维持的连接总量（长连接累积、受内存/线程限制），QPS是每秒处理的请求数（吞吐能力），连接多不代表吞吐高。


### SoftwareTesting-002-016 | ★★★☆☆

网页崩溃的原因可能是什么？

**答案：**
前端：内存泄漏、死循环、大量DOM渲染；后端/系统：服务宕机、资源耗尽（CPU/内存/连接数）、网关超时。


### SoftwareTesting-002-017 | ★★★☆☆

有个用户反馈上传头像失败，你如何分析原因？

**答案：**
先复现：检查图片格式/大小是否超限、网络与权限；抓包看请求是否发出、返回码；查后端日志/存储服务状态；区分前端校验、网关、后端、存储哪一层的问题。


### SoftwareTesting-002-018 | ★★★☆☆

APP 闪退的原因有哪些？

**答案：**
空指针等代码异常、内存不足被系统杀掉、ANR、兼容性问题（机型/系统版本）、缓存/数据损坏、权限被拒、热更新缺陷等。


### SoftwareTesting-002-019 | ★★★☆☆

偶然闪退（无法稳定复现）如何排查？

**答案：**
收集崩溃日志（logcat/崩溃平台如Bugly）、分析堆栈；按机型/系统/操作路径聚类找规律；加大压测/monkey复现；结合埋点还原操作场景。


### SoftwareTesting-002-020 | ★★★☆☆

10% 的用户反馈用不了某个功能，你将如何排查？

**答案：**
按用户特征聚类（灰度版本、地区运营商、机型、账号白名单/黑名单），确认是否灰度发布、CDN节点、网络策略、缓存或特定数据触发，逐步缩小范围定位共性。


### SoftwareTesting-002-021 | ★★★☆☆

登录的按钮不能点击，如何排查问题？

**答案：**
看前端：按钮是否被置灰（表单校验未过、disabled状态）、元素是否被遮挡、JS报错；抓包看接口返回是否异常导致状态异常；不同环境/账号对比。


### SoftwareTesting-002-022 | ★★★☆☆

压测的时候，QPS 一直上不去，你会怎么排查？

**答案：**
先确认施压机是否瓶颈（CPU、带宽、JMeter线程数/连接数）；再看网络与网关限流；然后看服务端：连接池/线程池打满、数据库慢查询、锁竞争、下游依赖超时等。


### SoftwareTesting-002-023 | ★★★☆☆

怎么判断一个 BUG 到底是前端的 BUG 还是后端的 BUG？

**答案：**
抓包看接口：请求参数错误多为前端，返回数据错误/状态码错误多为后端；接口正常但展示异常则是前端渲染问题。


### SoftwareTesting-002-024 | ★★★☆☆

对一台自动售货机进行测试用例设计，你会考虑哪些方面？

### SoftwareTesting-002-025 | ★★★☆☆

设计微信发红包的测试用例。

### SoftwareTesting-002-026 | ★★★☆☆

设计微信扫码支付的测试用例。

### SoftwareTesting-002-027 | ★★★☆☆

编写一个登录界面的测试用例。

**答案：**
功能（正确/错误账密、注册手机号不存在）、密码错误次数锁定、验证码（错误/过期/刷新）、记住密码、多端登录互踢、SQL注入、HTTPS、弱网提交、回车登录。


### SoftwareTesting-002-028 | ★★★☆☆

对一个接口编写测试用例，你会考虑哪些点？

**答案：**
参数校验（必填、类型、长度、边界）、业务场景（正常/异常分支）、返回码与数据结构断言、鉴权（无token/过期）、幂等与重复提交、并发、性能与安全（注入越权）。


### SoftwareTesting-002-029 | ★★★☆☆

微信红包是先计算每个人能获得的钱，还是当这个人点了之后再计算？说说你的理解。

拼手气红包通常在领取时实时计算（拆分算法按剩余金额随机），需要保证并发下金额总和守恒、先领后领期望公平。

功能（上下行、开关门、楼层选择、超载报警、紧急按钮）、界面/易用性（按钮高度、显示屏）、性能（载重、速度、等待时间）、可靠性安全（断电、门夹物、钢丝绳）、异常（停在两层之间）、兼容（不同楼宇）。


### SoftwareTesting-002-032 | ★★★☆☆

5000 个人抢购商品，只能 50 个人能抢到，你怎么设计压测并发数？

**答案：**
按峰值用户量与二八原则估算：5000×80%=4000，并发数峰值设为4000，同时验证限购/库存扣减在并发下不超卖。


### SoftwareTesting-002-033 | ★★★☆☆

微信里如果只有 B 看不到你发的朋友圈，其他朋友都可以看到，分析下可能是什么原因？

**答案：**
可能：B不是好友/被拉黑（A拉黑B或B拉黑A）、A设置不让他（B）看、A设置仅展示时间段、A删除了该条、B设置不看A的朋友圈；逐一排查权限与好友关系配置。
