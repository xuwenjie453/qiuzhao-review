### DataStructures-001-001 | ★★★★☆

数组和链表的底层差异与选型？

**答案：**
数组连续内存：O(1) 随机访问（地址=首址+偏移×元素大小）、尾部增删 O(1)（均摊，考虑扩容）、中间插入删除 O(n) 移动；链表节点离散+指针：任意位置已知节点增删 O(1)、随机访问 O(n)、每节点多指针开销且缓存不友好。现代 CPU 下"缓存局部性"常让数组完胜理论复杂度接近的场景——顺序遍历数组预取友好，链表每跳都是潜在缓存 miss。这也是 Java 场景 ArrayList 几乎默认胜 LinkedList 的底层原因（K-COL-006）。动态数组的扩容均摊分析要会：1.5~2 倍扩容使 n 次尾部追加总成本 O(n)，均摊 O(1)。


### DataStructures-001-002 | ★★★★★

哈希表的原理？冲突解决方法有哪些？

**答案：**
哈希表用哈希函数把 key 映射到桶下标，理想 O(1)。冲突不可避免（鸽巢原理），两类主流解法：链地址法（每个桶挂链/树，Java HashMap、Redis dict）与开放寻址法（冲突后按探测序列找下一个空位：线性探测、二次探测、双重哈希，ThreadLocalMap 用线性探测）。核心参数负载因子 α=元素数/桶数：链地址法 α 可 >1（查找退化为链长），开放寻址必须 α<1 且 0.75 左右就扩容（探测序列变长性能崩）。扩容 rehash 代价 O(n)，Redis 用渐进式 rehash 分摊（K-REDIS-002）。好的哈希函数要求：均匀、快速、确定性；密码学场景另需抗碰撞（SHA 系列）。


### DataStructures-001-003 | ★★★★☆

堆的结构与两个核心操作？建堆为什么是 O(n)？

**答案：**
二叉堆是完全二叉树存进数组（父 i，子 2i+1/2i+2），满足父≤子（小顶）或父≥子（大顶）。两个核心操作：上浮 sift-up（新元素与父比较交换，插入 O(logN)）、下沉 sift-down（删顶后尾元素补位，逐层与更优子交换，O(logN)）。建堆 O(n)：从最后一个非叶节点倒序下沉，数学上大部分节点下沉高度小，级数求和收敛为 O(n)，优于逐个插入的 O(n log n)。应用：TopK（K 大小堆，K-COL-012）、优先队列/定时任务、堆排序（原地 O(n log n)）、多路归并。


### DataStructures-001-004 | ★★★★☆

二叉树的遍历方式？非递归怎么写？

**答案：**
四种：前/中/后序（DFS 三态）与层序（BFS 队列）。递归版一行结束；非递归是面试手写高频：前序=栈+先右后左入栈；中序=指针一路压左链，弹出访问再转右；后序=前序变形（根右左）再逆序，或用 lastVisited 标记右子完成；层序=队列逐层 + 按层 size 分组。进阶：Morris 遍历 O(1) 空间（利用线索/前驱回指），能提一句是加分。遍历的应用映射：前序=序列化/复制、中序=BST 有序输出、后序=自底向上计算（高度、依赖）、层序=最短层级/按层处理。


### DataStructures-001-005 | ★★★★☆

二叉搜索树（BST）与红黑树的平衡原理？

**答案：**
BST：左<根<右，查找/插入/删除平均 O(log n)，有序输入退化为链表 O(n)——需要自平衡。AVL：严格平衡（左右高差 ≤1），查找快、插删旋转多，适合读密集。红黑树：放宽为"最长路径 ≤ 2×最短路径"的五条性质（节点红或黑；根黑；叶 NIL 黑；红节点子必黑，即无红红相连；任一节点到叶的黑高相等），用红黑染色+旋转把失衡修复摊销为 O(1) 次旋转，综合增删查表现均衡，工程首选：HashMap 树化桶、TreeMap、Linux CFS、epoll 就绪结构（历史）。记忆抓手：红黑树 ≈ "2-3-4 树"的二元编码——理解等价变换就不用死背插删案例。


### DataStructures-001-006 | ★★★☆☆

布隆过滤器、HyperLogLog、跳表这些"概率/概率型结构"的原理？

**答案：**
三个"用误差换空间"的代表：①布隆过滤器（K-REDIS-013）：位数组+k 哈希，判"一定不在/可能在"，不支持删除；②HyperLogLog：基数估算，利用"哈希值前导零的最大值决定均匀随机分布的分位数"原理，分桶调和平均降低方差，16384 桶时误差 ~0.81%，固定 12KB 计数上亿；③跳表：多层链表，节点以 1/4 概率晋升上层，期望查找 O(log n)，实现简单支持范围与排名（Redis ZSET）。共同哲学：大数据量下牺牲确定性换内存与速度，前提是业务能接受误差界。


### DataStructures-001-007 | ★★★★☆

图的存储与遍历？BFS 和 DFS 各自适合什么问题？

**答案：**
存储两种：邻接矩阵（O(V²) 空间，查边 O(1)，稠密图）、邻接表（O(V+E)，稀疏图标准选择，反向边可再存逆邻接表）。遍历：BFS 用队列逐层扩展——无权图最短路径、层级关系（社交度数、二叉树层序）；DFS 用栈/递归深入——连通性、环检测、拓扑排序（入度法属 BFS 家族）、路径枚举。复杂度均 O(V+E)。有向无环图（DAG）+ 拓扑排序是任务调度依赖的标准模型；带权最短路：Dijkstra（非负权，堆优化 O(E logV)）、Bellman-Ford（可负权）/SPFA、Floyd（多源 O(V³)）。工程图问题大多收敛到这几件套。


### DataStructures-001-008 | ★★★☆☆

前缀树（Trie）、并查集、线段树各自的用途？

**答案：**
三个"专用武器"：①Trie 前缀树：按字符逐层分叉，前缀检索 O(单词长)，应用输入提示、敏感词、路由匹配（HTTP 路由树）；空间换时间，可用双数组压缩。②并查集（Union-Find）：管理不相交集合的合并与查询，路径压缩+按秩合并后近乎 O(1)（反 Ackermann），应用连通性（朋友圈、网络连通）、Kruskal 最小生成树、动态等价类。③线段树：区间问题的标准结构，单点/区间修改+区间查询 O(log n)，懒标记支持区间整体赋值/加；变体树状数组（BIT）代码更短，适合前缀和可逆类问题。选择口诀：前缀找 Trie、合并找并查集、区间找线段树。


### DataStructures-001-009 | ★★★☆☆

二叉树节点计算

一棵二叉树有 20 个度为 2 的节点，则叶子节点数为：

A. 19
B. 20
C. 21
D. 无法确定

**答案：** C

**解析：**
- A：错误。由公式 n0 = n2 + 1 应为 21。
- B：错误。差 1。
- C：正确。二叉树中 n0 = n2 + 1（由总边数 = 总节点数 - 1 与度数关系推导）。
- D：错误。n0 由 n2 唯一确定。

n0 = n2 + 1 的推导：边数 = n1 + 2n2 = n0+n1+n2-1。


### DataStructures-001-010 | ★★★☆☆

排序算法稳定性

下列排序算法中，属于稳定排序的有：

A. 冒泡排序
B. 快速排序
C. 归并排序
D. 堆排序

**答案：** A、C

**解析：**
- A：正确。相邻交换不改变相等元素相对次序。
- B：错误。分区交换会打乱相等元素相对次序。
- C：正确。归并时相等元素优先取左半部分，保持稳定。
- D：错误。堆调整的长距离交换破坏稳定性。

稳定：冒泡、插入、归并、计数；不稳定：快排、堆排、选择、希尔。


### DataStructures-001-011 | ★★★★☆

A. O(n log n)、O(n log n)
B. O(n log n)、O(n²)
C. O(n²)、O(n log n)
D. O(n)、O(n²)

### DataStructures-001-014 | ★★★☆☆

### DataStructures-001-015 | ★★★☆☆

### DataStructures-001-020 | ★★☆☆☆

中缀转后缀

中缀表达式 `A + B * C - (D / E)` 的后缀表达式是：

A. `A B C * + D E / -`
B. `A B + C * D E / -`
C. `A B C * + D E - /`
D. `A B C + * D / E -`

**答案：** A

**解析：**
A 对，B*C 先结合→`B C *`，加→`A B C * +`，括号内 `D E /`，最后减；B 错，把 + 先算（丢了优先级）；C 错，减与除的顺序错；D 错，完全错乱。

运算符优先级+左结合；后缀无需括号。
