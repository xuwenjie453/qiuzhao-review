### JUC-003-001 | ★★★★★

AQS 的核心思想是什么？state 和 CLH 等待队列在加锁流程中分别起什么作用？

**答案：**
AQS 用 volatile int state 表示同步状态，内置 FIFO 的 CLH 变体双向队列排队阻塞线程；获取锁失败的线程包装成 Node 入队 park，释放锁时唤醒队头后继节点。


### JUC-003-002 | ★★★★★

如何用 AQS 实现一个可重入的公平锁？

**答案：**
在 tryAcquire 中先判断 state 是否为 0，为 0 时用 hasQueuedPredecessors() 检查队列是否有等待线程，有则入队；同一线程再次获取则 state 加 1 实现重入，释放时逐次减 1。


### JUC-003-003 | ★★★★★

AQS 的 Condition 条件队列是怎么工作的？和同步队列是什么关系？

**答案：**
await() 把当前线程节点从同步队列移到该 Condition 的条件队列并释放锁，signal() 再把节点转移回同步队列排队抢锁；一个 AQS 同步器可对应多个条件队列。


### JUC-003-004 | ★★★★☆

公平锁和非公平锁的性能差异为什么很大？非公平锁吞吐量为什么更高？
SRC2: https://www.xiaolincoding.com/interview/juc.html

**答案：**
非公平锁新线程可直接 CAS 抢锁，减少线程挂起/唤醒的上下文切换和 park 开销，但可能导致队列中线程长期拿不到锁（饥饿）。


### JUC-003-005 | ★★★★★

线程池的核心线程会被回收吗？核心线程空闲时处于什么状态？

**答案：**
默认不回收，allowCoreThreadTimeOut(true) 后可回收；核心线程空闲时在阻塞队列的 take() 上处于 WAITING 状态，允许超时回收时用 poll(timeout) 处于 TIMED_WAITING。


### JUC-003-006 | ★★★★★

线程池中线程抛出异常后，这个线程会被销毁还是复用？

**答案：**
通过 execute() 提交时异常直接抛出，该 worker 线程会被销毁并由线程池补建新线程；通过 submit() 提交时异常被吞进 Future，线程不销毁继续复用。


### JUC-003-007 | ★★★★☆

CallerRunsPolicy 拒绝策略有什么风险？如何解决？

**答案：**
被拒绝任务回退到调用者线程执行，会阻塞 Tomcat 等调用线程拖慢整体吞吐，且任务可能乱序/丢审计；可通过扩大有界队列、降级落库、改用持久化异步补偿来缓解。


### JUC-003-008 | ★★★★★

如何动态修改线程池的参数？setMaximumPoolSize 之后多余的核心线程怎么处理？

**答案：**
ThreadPoolExecutor 本身提供 setCorePoolSize/setMaximumPoolSize/setKeepAliveTime 等运行时方法，可结合配置中心动态下发；调大核心数会立即预启动线程补齐，调小后多余的空闲线程在下次 poll 超时后被回收。


### JUC-003-009 | ★★★★★

如何设定线程池的大小？CPU 密集型和 I/O 密集型分别怎么估算？

**答案：**
CPU 密集型取 N+1 左右，I/O 密集型按 N * (1 + 等待时间/计算时间) 放大；更可靠的做法是压测结合下游容量（连接池、下游 QPS）共同确定。


### JUC-003-010 | ★★★★☆

线程数为什么要和下游容量一起设计？有界队列应该设置多大？

**答案：**
线程再快也会被下游（DB 连接池、下游服务 QPS）卡死，线程数 × 单线程吞吐应与下游容量匹配；队列大小按"可接受的排队延迟 = 队列长度 / 处理速率"反推，避免请求在队列里等到超时。


### JUC-003-011 | ★★★★☆

CallerRunsPolicy 能形成背压吗？

**答案：**
能，调用者线程执行任务会天然拖慢上游提交速度，形成简单背压；但如果调用者是 Tomcat 工作线程，会占用 Web 线程池容量，需要评估影响面。


### JUC-003-012 | ★★★★☆

异步任务抛出的异常为什么容易丢？怎么处理？

**答案：**
submit() 会把异常封装进 Future，不 get() 就看不到；execute() 抛出的异常若未设置 UncaughtExceptionHandler 也会被吞。应主动捕获、设置异常处理器或用 CompletableFuture 的 exceptionally/whenComplete 兜底。


### JUC-003-013 | ★★★★★

线程池应该监控哪些指标？

**答案：**
活跃线程数、队列长度/剩余容量、已完成任务数、拒绝次数、任务执行耗时分布，配合告警阈值判断饱和与泄漏。


### JUC-003-014 | ★★★★☆

核心线程数设置为 0 可不可以？

**答案：**
可以，core=0 时所有任务先进队列，由非核心线程在 keepAliveTime 内处理；但若同时使用无界队列（如 newFixedThreadPool 的 LinkedBlockingQueue），线程数会恒为 0/1 造成任务堆积。


### JUC-003-015 | ★★★★★

提交给线程池中的任务可以被撤回吗？

**答案：**
submit 返回的 Future 可用 cancel(true) 中断正在执行的任务、cancel(false) 只取消还未开始的任务；已经执行到不可中断代码（如 IO）的任务无法强制停止。


### JUC-003-016 | ★★★★☆

ThreadLocalMap 的 key 是怎么计算出来的？哈希冲突如何解决？
SRC2: https://notes.kamacoder.com/interview/llm/20260506bytedance.html

**答案：**
key 为 ThreadLocal 对象的弱引用，hash 值用 threadLocalHashCode = AtomicInteger increments(0x61c88647 黄金分割数) 递增；冲突用开放地址法（线性探测）向后找空位，不像 HashMap 用链地址法。


### JUC-003-017 | ★★★★☆

ThreadLocal 为什么会发生内存泄漏？为什么 key 要设计成弱引用？

**答案：**
Entry 继承 WeakReference<ThreadLocal>，key 被回收后变成 null 但 value 仍被 ThreadLocalMap 强引用，线程池线程长存导致 value 无法回收；key 用弱引用是为了让 ThreadLocal 实例可被 GC，配合 set/get/remove 中的探测式清理清理 stale entry。


### JUC-003-018 | ★★★★☆

ThreadLocalMap 的探测式清理和启发式清理分别是怎么做的？

**答案：**
探测式清理（expungeStaleEntry）从某个 stale slot 开始连续向后扫描，把 key 为 null 的 entry 置空并 rehash 后续 entry；启发式清理（cleanSomeSlots）是对数式抽样探测，发现 stale entry 才触发一段连续清理。


### JUC-003-019 | ★★★★☆

如何跨线程传递 ThreadLocal 的值？

**答案：**
用 InheritableThreadLocal 可在子线程创建时继承父线程的值，但线程池中线程复用不会重新继承，需要用阿里 TransmittableThreadLocal（TTL）在任务提交/执行时做快照传递。


### JUC-003-020 | ★★★★☆

ConcurrentHashMap 是怎么实现线程安全和并发的？CAS 和 synchronized 分别用在什么场景？
SRC2: https://www.xiaolincoding.com/backend_interview/internet_medium/58.html

**答案：**
1.8 中桶为空时用 CAS 插入新节点，桶头非空时 synchronized 锁住桶头节点链式插入；扩容和 size 计数用 CAS 配合 transfer/CounterCell 分散计数。


### JUC-003-021 | ★★★★☆

ConcurrentHashMap 支持并发写，它的 size() 函数是怎么实现的？

**答案：**
用 baseCount + CounterCell[] 分段计数（类似 LongAdder），put 时 CAS baseCount 失败就散列到 CounterCell 上累加，size() 时汇总 baseCount 与所有 CounterCell，是一个弱一致的估计值。


### JUC-003-022 | ★★★★☆

ConcurrentHashMap 1.7 的扩容 rehash 是怎么做的？

**答案：**
1.7 Segment 内部扩容只锁一个 Segment，该段内 HashEntry 数组按旧容量翻倍重建并 rehash，其余 Segment 不受影响，实现并发扩容。


### JUC-003-023 | ★★★★★

什么是虚拟线程？它和平台线程有什么区别？

**答案：**
JDK 21 正式发布的轻量级线程，由 JVM 调度挂载到少量载体线程（carrier thread）上运行，阻塞时不阻塞 OS 线程，创建成本 KB 级，可百万级并发；适合 I/O 密集而非 CPU 密集任务。


### JUC-003-024 | ★★★★★

虚拟线程的 Pinning（钉住）是什么？JDK 21 里 synchronized 还能不能用？

**答案：**
虚拟线程在 synchronized 块内阻塞或执行 native 方法时无法从载体线程卸载，会钉住载体线程放大阻塞影响；JDK 21 仍可用 synchronized，只是热点阻塞场景建议改 ReentrantLock，JDK 24 起 JEP 491 已修复 synchronized 导致的 pinning。


### JUC-003-025 | ★★★★★

虚拟线程要不要池化？

**答案：**
不要，虚拟线程创建成本极低应即用即弃，池化反而限制并发并可能引起资源饥饿；需要限流时应使用 Semaphore 等控制对下游的并发访问。
