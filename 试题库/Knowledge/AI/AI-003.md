### AI-003-001 | ★★★★☆

Function Call 是什么？底层怎么实现？如果同时触发多个 Function Call 怎么处理？

**答案：**
模型按 schema 输出结构化的工具调用 JSON，由应用侧实际执行并把结果回填上下文，模型本身不执行；并发触发时可并行返回多个 tool_calls，由框架并发执行后按 id 对应回填。


### AI-003-002 | ★★★★☆

MCP 是什么协议？解决什么问题？和 Function Call、A2A 有什么区别？

**答案：**
MCP 是工具/资源访问的标准化协议（JSON-RPC over stdio/HTTP），把 M×N 的模型-工具集成收敛为 M+N；Function Call 是模型能力，MCP 是工具接入标准，A2A 则是 Agent 之间的协作协议，解决 MCP 覆盖不了的 Agent 互操作问题。


### AI-003-003 | ★★★★☆

Agent 的记忆系统怎么设计？上下文快满的时候怎么办？

**答案：**
短期记忆用上下文窗口内消息历史，长期记忆外置到向量库/结构化存储按需检索；快满时做摘要压缩、滑动窗口裁剪、关键信息外置存储，检索时再注入。


### AI-003-004 | ★★★★★

如果 Agent 要操作数据库，怎么保证它不会误删数据？什么是 Prompt Injection？怎么防御？

**答案：**
最小权限账号、只读视图、SQL 审计与危险语句白名单、人审卡点、沙箱执行。Prompt Injection 是通过文档/网页等外部内容注入指令劫持 Agent；防御：内容隔离标记、指令与数据分层、输出过滤、工具调用二次确认。


### AI-003-005 | ★★★★☆

生产环境的 Agent 常踩什么坑？Token 消耗很大，怎么优化成本？

### AI-003-006 | ★★★★☆

你们 RAG 检索到了但答不对，怎么办？RAG 检索到了正确信息，LLM 还是编造，怎么处理？

### AI-003-007 | ★★★★★

GraphRAG 和传统 RAG 的本质区别是什么？索引阶段怎么工作？查询阶段有几种方式？

**答案：**
传统 RAG 找相似文本块，GraphRAG 先用 LLM 抽取实体关系建图+社区摘要，能回答全局性/关系型问题；查询分 local（沿实体邻域）和 global（社区摘要 Map-Reduce 汇总）两种。


### AI-003-008 | ★★★★★

GraphRAG 落地遇到什么问题？LightRAG 和 GraphRAG 有什么区别，怎么选？

**答案：**
GraphRAG 索引要大量 LLM 调用，成本可能是普通 RAG 的 10 倍以上且增量更新困难；LightRAG 用轻量抽取+双层检索（实体/主题）+支持增量插入，成本低易更新。全局复杂分析、更新少选 GraphRAG，高频更新、预算有限选 LightRAG。


### AI-003-009 | ★★★★☆

为什么检索之后还要 Rerank？混合检索的权重怎么调？

**答案：**
向量召回是双塔式粗排，Rerank 用交叉编码器对 query-文档精细打分显著提升排序质量；混合检索（向量+BM25）权重按领域调参，关键词强的场景（代码、术语）提高 BM25 权重，再统一 Rerank。


### AI-003-010 | ★★★★☆

文档更新了，向量索引怎么更新？RAG 系统的端到端延迟怎么优化？

**答案：**
按文档 ID 删除旧 chunk 再重新切片向量化写入（保留 chunk 元数据做增量），配合监听数据变更的管道；延迟优化：缓存 query 向量与高频结果、流式输出、精简 Rerank 模型、并行检索。


### AI-003-011 | ★★★★★

为什么 vLLM 能够加快大模型推理速度？

**答案：**
PagedAttention 把 KV Cache 按固定 block 分页管理，显存碎片和预留浪费大幅降低、batch 并发变大；叠加 Continuous Batching 动态插拔请求、抢占调度与 Chunked Prefill，吞吐比朴素批处理高数倍。


### AI-003-012 | ★★★★☆

什么是 Continuous Batching（连续批处理）？它和 Static Batching 相比有什么优势？

**答案：**
静态批处理要等整批请求全部完成才能组新批，长短请求互相拖累且 padding 浪费算力；连续批处理在请求完成的迭代步立即补入新请求，序列级调度使 GPU 利用率大幅提升。


### AI-003-013 | ★★★★☆

大模型训练时的并行方式有哪些？数据并行、张量并行、流水线并行分别解决什么问题？
SRC2: https://juejin.cn/post/7640176027144110126

**答案：**
DP 切数据提吞吐（各卡完整模型+AllReduce 梯度）；TP 切单层大矩阵算子解决单卡放不下单层的问题（通信频繁适合机内 NVLink）；PP 按层切解决模型深度/层数问题（micro-batch 减少 bubble），三者可组合成 3D 并行。


### AI-003-014 | ★★★★☆

ZeRO 1/2/3 分别切分了什么？解决了什么问题？

**答案：**
数据并行的冗余主要在优化器状态/梯度/参数：ZeRO-1 切优化器状态，ZeRO-2 再切梯度，ZeRO-3 把参数也切片（前向/反向时 all-gather 临时聚合），逐级降低显存冗余但通信量增加。
