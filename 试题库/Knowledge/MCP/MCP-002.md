### MCP-002-001 | ★★★★☆

什么是MCP（模型上下文协议）？讲讲它的核心内容？

**答案：**
MCP是Anthropic提出的开放协议，统一模型与外部工具/数据源的连接方式，包含客户端、服务端和资源、工具、提示等原语。


### MCP-002-002 | ★★★★☆

MCP由哪几部分组成？

**答案：**
Host宿主应用、MCP Client客户端、MCP Server服务端；服务端提供Tools、Resources、Prompts三类能力。


### MCP-002-003 | ★★★★☆

MCP和Function Calling有什么区别？有没有实际跑过MCP？

**答案：**
FC是模型侧能力、每个应用需单独集成工具；MCP是标准化协议，工具以服务形式解耦，一次接入处处可用。


### MCP-002-004 | ★★★★☆

Function Calling也属于工具调用，请问什么场景下使用Function Calling，什么场景下使用MCP？

**答案：**
Function Calling适合场景固定、服务方自己定义少量工具、快速集成自身API的场合；MCP适合需要接入大量第三方/外部系统、工具要跨应用复用、生态化共享的场合。两者是层次关系：MCP是标准化协议，MCP server注册的工具最终仍以function call形式暴露给模型。


### MCP-002-005 | ★★★★☆

为什么有些特定的推理模型不支持MCP协议？

**答案：**
MCP依赖宿主客户端实现协议并与模型的function calling能力对接；部分推理模型（或其托管API）不开放原生工具调用/结构化输出接口，或其长思维链推理流程与"调用-等待结果-继续生成"的中断恢复机制不兼容，因此无法直接挂载MCP。本质是缺少函数调用接口或协议适配，而非MCP协议本身的限制。


### MCP-002-006 | ★★★★☆

Skill是什么？MCP和Agent Skill的区别是什么？

**答案：**
Agent Skill是把领域知识、操作流程和脚本封装成文件夹（SKILL.md+资源文件）供Agent按需加载的机制，通过渐进式披露（启动只读元数据，相关时才读全文/执行脚本）教会模型"怎么做"。与MCP的区别：MCP是连接外部工具与数据源的标准化协议，提供"能调用什么"的实时接口；Skill封装知识与流程、无需常驻服务进程。二者互补，常配合使用。


### MCP-002-007 | ★★★★☆

Function Calling、Skill、MCP这三个有什么区别？

**答案：**
三者层次不同：Function Calling是模型层的原子能力（模型按JSON schema生成调用参数，绑定厂商API）；MCP是开放协议（统一模型应用与外部工具/数据源的连接，提供tools/resources/prompts，client-server架构）；Skill是能力封装（以文档+脚本沉淀可复用的知识与流程，按需渐进加载）。实践中常组合：通过FC调用MCP工具，用Skill指导何时以及如何组合调用。


### MCP-002-008 | ★★★★☆

什么是A2A协议？它和MCP协议的区别是什么？

**答案：**
A2A（Agent2Agent）是Agent之间互操作的开放协议，由Google发起并捐赠给Linux基金会：Agent通过Agent Card声明能力、以Task为单位互相发现、委派与回传结果。与MCP的区别：MCP解决Agent与工具/数据源（agent-to-tool）的连接，A2A解决Agent与Agent（agent-to-agent）的协作通信，二者互补而非替代。


### MCP-002-009 | ★★★★☆

MCP协议通常采用什么通信方式？

**答案：**
基于JSON-RPC 2.0，传输层可用stdio（本地）或HTTP+SSE/Streamable HTTP（远程）。


### MCP-002-010 | ★★★★☆

说说WebSocket和SSE通信的区别及局限性？

**答案：**
WebSocket全双工、需维护连接；SSE单向（服务器到客户端）、基于HTTP更简单，跨源重连受限。


### MCP-002-011 | ★★★★☆

MCP（工具标准化接口）和Skill（能力封装复用）在Agent系统中分别起什么作用？

**答案：**
MCP负责"标准化接口"：把外部系统、API、数据源以统一协议暴露为工具，让Agent即插即用地获得执行能力，避免为每个模型各写一遍集成。Skill负责"能力封装复用"：把操作流程、领域知识、最佳实践文档化并按需加载，教会Agent在合适时机正确组合工具完成复杂工作流。一个提供原子能力接入，一个提供方法论与流程复用。


### MCP-002-012 | ★★★★☆

Agent接入的工具都是本地的，还是MCP？两者怎么选？

**答案：**
两者都常见：自用、场景固定、只服务于单一应用的工具，直接实现为本地function call最简单、延迟最低；需要跨应用复用、接入第三方系统、多客户端/团队共享维护时用MCP。选型看复用范围与维护成本：一次性集成本地即可，生态化、多端消费选MCP。
