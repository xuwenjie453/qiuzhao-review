### Python-001-001 | ★★★★☆

Python 可变与不可变类型的区别？

**答案：**
不可变类型：int、float、str、tuple、frozenset——对象创建后内容不可修改，"修改"操作实际是创建新对象并让变量重新指向；可变类型：list、dict、set——可原地修改。影响三个行为：①作为函数默认参数时，可变默认参数会被多次调用共享（著名的坑，正确做法默认 None）；②作为字典 key 要求可哈希，可变类型不可哈希不能作 key；③赋值/传参是引用传递语义，`b = a` 只是共享引用，改 b 的内容 a 可见，要独立副本需拷贝（K-PY-002）。


### Python-001-002 | ★★★★☆

深拷贝和浅拷贝？

**答案：**
赋值 `b = a` 不拷贝，只共享引用。浅拷贝（`a.copy()`、`list(a)`、`copy.copy`）：创建新容器，但元素仍是原对象的引用——嵌套结构内层共享；深拷贝（`copy.deepcopy`）：递归拷贝所有层级，完全独立。验证方式：改 `b[0]`（不可变元素替换）a 不受影响，改 `b[2][0]`（可变嵌套）浅拷贝时 a 同步变化、深拷贝时 a 不变。dict 的 `dict.copy()` 与 `dict(**a)` 都是浅拷贝。


### Python-001-003 | ★★★★☆

迭代器和生成器是什么？

**答案：**
迭代器：实现 `__iter__` 与 `__next__` 的对象，逐个产出元素、耗尽抛 StopIteration；可迭代对象（list/str/dict）通过 `iter()` 获得迭代器。生成器：用 `yield` 的函数或生成器表达式，是迭代器的简洁写法——调用不执行函数体，每次 `next()` 执行到 yield 暂停并返回值，恢复时从断点继续。价值：**惰性求值**，边生成边消费，处理大文件/大序列时内存 O(1)（逐行读日志、无限序列）；还能实现协程式流程。range 是惰性的、map/filter 返回迭代器，Python 3 的主流取向就是惰性。


### Python-001-004 | ★★★★☆

装饰器是什么？

**答案：**
装饰器是"接收函数并返回新函数"的高阶函数，用 `@decorator` 语法在不修改原函数的前提下增强行为（日志、计时、缓存、权限、重试）。本质是 `f = decorator(f)` 的语法糖；带参数的装饰器是"三层函数"（装饰器工厂→装饰器→包装函数）；`functools.wraps` 保留原函数元信息（否则 __name__ 变成 wrapper）。标准库典型：`@functools.lru_cache`（记忆化，直接优化递归 ACM 题）、`@staticmethod/@classmethod`。


### Python-001-005 | ★★★★☆

GIL 是什么？Python 的并发怎么选？

**答案：**
GIL（全局解释器锁）：CPython 中同一时刻只允许一个线程执行 Python 字节码。后果：**多线程无法利用多核做 CPU 并行**——CPU 密集任务用 multiprocessing（多进程）或绕开 GIL 的库（NumPy 内部 C 层并行）；**IO 密集任务多线程仍然有效**——线程在等 IO 时会释放 GIL（requests、文件、sleep 场景）；asyncio 单线程事件驱动适合海量高并发 IO。Python 3.13 起实验性 free-threading（可关 GIL 构建）开始落地，但主流仍是带 GIL 的版本。一句话选型：CPU 密集→多进程/原生扩展；IO 密集→多线程或 asyncio。


### Python-001-006 | ★★★★☆

可变默认参数

```python
def add(x, lst=[]):
    lst.append(x)
    return lst

print(add(1))
print(add(2))
```
输出是：

A. `[1]` 然后 `[2]`
B. `[1]` 然后 `[1, 2]`
C. `[1]` 然后 `[2, 1]`
D. 抛出异常

**答案：** B

**解析：**
- A：错误。默认参数在函数定义时求值一次，多次调用共享同一个 list 对象。
- B：正确。两次调用作用于同一个默认列表，第二次 append 在第一次结果上继续。
- C：错误。append 是尾插。
- D：错误。语法完全合法，这正是陷阱所在。

默认参数只求值一次；可变默认参数跨调用共享，正确写法默认 None 在函数体内新建。


### Python-001-007 | ★★★☆☆

切片与负索引

```python
s = "abcdef"
print(s[1:4], s[::-1], s[-2:])
```
输出是：

A. `bcd fedcba ef`
B. `bcde fedcba ef`
C. `bcd abcdef ef`
D. `bcd fedcba de`

**答案：** A

**解析：**
- A：正确。`s[1:4]` 取下标 1~3（含头不含尾）为 "bcd"；`s[::-1]` 反转 "fedcba"；`s[-2:]` 从倒数第二个到末尾 "ef"。
- B：错误。`s[1:4]` 不含下标 4，不会是 "bcde"。
- C：错误。反转项错误。
- D：错误。`s[-2:]` 是最后两个字符 "ef"，不是 "de"。

切片含头不含尾；`[::-1]` 反转；负索引 -1 是最后一个。


### Python-001-008 | ★★★★☆

浅拷贝验证

```python
import copy
a = [1, [2, 3]]
b = copy.copy(a)
b[0] = 9
b[1].append(4)
print(a)
```
输出是：

A. `[1, [2, 3]]`
B. `[9, [2, 3, 4]]`
C. `[1, [2, 3, 4]]`
D. `[9, [2, 3]]`

**答案：** C

**解析：**
- A：错误。b[1].append(4) 修改的是共享的内层列表，a 会看到。
- B：错误。b[0]=9 只改了 b 的第一层引用，a[0] 仍是 1。
- C：正确。浅拷贝复制第一层：b[0]=9 不影响 a；但内层 [2,3] 是共享引用，append(4) 两边同时可见。
- D：错误。a[0] 未被修改。

浅拷贝=新容器旧元素；嵌套可变结构需 deepcopy 才独立。


### Python-001-009 | ★★★☆☆

生成器行为

```python
def g():
    yield 1
    yield 2

x = g()
print(sum(x))
print(sum(x))
```
输出是：

A. `3` 然后 `3`
B. `1` 然后 `2`
C. `3` 然后 `0`
D. 抛出 StopIteration 异常

**答案：** C

**解析：**
- A：错误。生成器是一次性的，耗尽后不再产出。
- B：错误。sum 消费整个迭代器，不是逐个 next。
- C：正确。第一次 sum 消费完 1 和 2 得 3；生成器已耗尽，第二次 sum 对空迭代器求和得 0。
- D：错误。sum 内部正常处理 StopIteration，不向外抛。

生成器/迭代器一次性消费，耗尽即空。


### Python-001-010 | ★★★☆☆

is 与 ==

```python
a = 1000
b = 1000
print(a is b, a == b)
```
在 CPython 标准交互环境下的输出是：

A. `True True`
B. `False True`
C. `True False`
D. `False False`

**答案：** B

**解析：**
- A：错误。小整数缓存区间是 -5~256，1000 在区间外，两个对象地址不同。
- B：正确。`is` 比较身份（同一对象）为 False；`==` 比较值相等为 True。
- C：错误。值相等时 == 必为 True。
- D：错误。值相等 == 必为 True。

is 只用于身份判断（如 x is None）；值比较一律 ==；小整数缓存使小数值 is 恰好为 True，是陷阱不是保证。


### Python-001-011 | ★★★★☆

GIL 与多线程

关于 CPython 的 GIL，下列说法正确的有：

A. 同一时刻仅一个线程执行 Python 字节码
B. 多线程程序无法利用多核加速 CPU 密集型任务
C. IO 密集型任务使用多线程仍然可以带来吞吐提升
D. GIL 保证了 Python 对象的所有复合操作天然线程安全

**答案：** A、B、C

**解析：**

GIL 选型：CPU 密集→多进程；IO 密集→线程/asyncio。


### Python-001-012 | ★★☆☆☆

dict 遍历与修改

```python
d = {"a": 1, "b": 2}
for k in d:
    if d[k] == 1:
        del d[k]
```
最可能的结果是：

A. 正常删除 key "a"
B. 抛出 RuntimeError（遍历中修改字典大小）
C. 静默忽略删除
D. 删除所有 key

**答案：** B

**解析：**
- A：错误。Python 3 中迭代字典时改变大小会触发异常（本例删除首个元素后继续迭代即触发）。
- B：正确。RuntimeError: dictionary changed size during iteration。
- C：错误。不会静默。
- D：错误。直接异常，不会删完。

遍历时修改容器大小的正确姿势：遍历 `list(d.keys())` 快照，或收集后统一删除，或用推导式重建。


### Python-001-013 | ★★★★☆

列表乘法陷阱

```python
g = [[0] * 3] * 3
g[0][0] = 1
print(g)
```

输出是：

A. `[[1, 0, 0], [0, 0, 0], [0, 0, 0]]`
B. `[[1, 0, 0], [1, 0, 0], [1, 0, 0]]`
C. `[[1, 1, 1], [0, 0, 0], [0, 0, 0]]`
D. 报错

**答案：** B

**解析：**
`[[0]*3]*3` 复制的是同一个内层列表的引用 3 次，改一处三处同步；正确创建方式 `[[0]*3 for _ in range(3)]`；A 是深独立列表的行为；C 错位；D 合法。

`*` 复制的是引用（对可变元素）；列表推导每次新建。


### Python-001-014 | ★★★☆☆

字典合并与覆盖

### Python-001-015 | ★★★☆☆

闭包晚绑定

```python
fs = [lambda: i for i in range(3)]
print([f() for f in fs])
```

输出是：

A. `[0, 1, 2]`
B. `[2, 2, 2]`
C. `[3, 3, 3]`
D. 报错

**答案：** B

**解析：**
lambda 捕获的是变量 i 本身（引用），循环结束 i=2，三个函数都返回 2；要各自捕获需默认参数 `lambda i=i: i`；A 是期望但错；C 越界值不存在（range 结束于 2）。

闭包晚绑定；默认参数在定义时求值可固化。


### Python-001-016 | ★★★☆☆

sorted 的 key

`sorted(["bb", "a", "ccc"], key=lambda s: (-len(s), s))` 的结果是：

A. `['a', 'bb', 'ccc']`
B. `['ccc', 'bb', 'a']`
C. `['bb', 'a', 'ccc']`
