### JVM-003-001 | ★★★★☆

遇到过线上 Full GC 频繁的情况吗？你会怎么排查？

**答案：**
先看 GC 日志和 jstat -gcutil 确认频率与回收后堆占用，jmap -histo 或 dump 后用 MAT 找占大头的对象和 GC Root 引用链，区分内存泄漏（缓存/ThreadLocal/连接未释放）与堆太小/大对象直接进老年代，再调整堆参数或修复代码。


### JVM-003-002 | ★★★★☆

服务 CPU 打满后怎么排查？进程、线程、代码位置分别用什么命令定位？

**答案：**
top 找到占用高的 Java 进程，top -Hp <pid> 找到具体线程，printf '%x' 把线程号转十六进制后在 jstack 快照里匹配 nid 定位到代码栈；也可用 arthas 的 dashboard/thread 一键定位。


### JVM-003-003 | ★★★★☆

怎么看一个 Java 进程占用多少堆内存、栈内存？讲几个 JVM 内存调优和故障处理工具。

**答案：**
jmap -heap / jstat -gc 看堆与各代占用，jstack 看线程与栈；常用工具有 jps、jstat、jinfo、jmap、jstack、jcmd 以及 VisualVM、MAT、arthas。


### JVM-003-004 | ★★★★☆

minorGC、majorGC、fullGC 的区别是什么？什么场景会触发 Full GC？

**答案：**
Minor GC 回收年轻代，频繁且快；Major GC 通常指老年代回收（CMS 并发）；Full GC 整堆+方法区。触发场景：老年代空间不足、元空间不足、System.gc()、空间分配担保失败、CMS concurrent mode failure 等。


### JVM-003-005 | ★★★★☆

CMS 和 G1 的区别是什么？什么情况下使用 CMS，什么情况下使用 G1？
SRC2: https://notes.kamacoder.com/interview/java/bytedance-interview-round2-1-1.html

**答案：**
CMS 按分代+标记清除，关注最短停顿但有内存碎片和 concurrent mode failure 风险；G1 把堆划成 Region、可预测停顿、整体标记整理+Region 间复制，适合大堆（6G+）；JDK9 后 CMS 被移除，大堆低延迟选 G1/ZGC。


### JVM-003-006 | ★★★★☆

G1 回收器的特色是什么？

**答案：**
Region 化堆布局、按回收价值排序的停顿预测模型（-XX:MaxGCPauseMillis），并发标记、SATB 记录引用变化，回收时优先收集"垃圾最多"的 Region 集合，从而把停顿控制在目标内。


### JVM-003-007 | ★★★★☆

内存泄漏和内存溢出的区别是什么？JVM 内存结构有哪几种 OOM 情况？有具体的例子吗？

**答案：**
泄漏是对象不再使用但无法回收（如 ThreadLocal 未 remove、静态集合缓存无淘汰），累积后引发溢出；溢出是内存不够分配。常见有堆 OOM（大集合/泄漏）、元空间 OOM（动态类生成）、栈 StackOverflowError（深递归）、直接内存 OOM（NIO Buffer）。


### JVM-003-008 | ★★★★☆

什么是 JIT、逃逸分析、锁消除、栈上分配和标量替换？

**答案：**
JIT 即时编译热点代码并优化；逃逸分析判断对象是否逃出方法/线程，据此做优化：未逃逸对象可标量替换拆成基本量分配在栈上（HotSpot 未真正实现栈上分配，靠标量替换实现），单线程使用的锁可被消除。


### JVM-003-009 | ★★★★★

Arthas 的原理是什么？线上怎么用 Arthas 排查 CPU 飙高和慢方法？
SRC2: https://blog.csdn.net/Nuan_Feng/article/details/161544922

**答案：**
Arthas 基于 Java Agent + Instrument 字节码增强Attach 到 JVM。CPU 飙高：dashboard → thread -n 3 找高 CPU 线程 → thread <tid> 看栈；慢方法：trace 类名 方法名 '#cost>500' 按耗时过滤，watch 观察入参出参。
