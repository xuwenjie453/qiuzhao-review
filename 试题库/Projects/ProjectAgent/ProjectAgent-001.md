### ProjectAgent-001-001 | ★★★★☆

你的 Agent 项目为什么需要 Agent？（Workflow 不行吗）

**答案：**
任务特征分析（路径是否可枚举、环境变化频率、决策复杂度）→ 为什么纯 Workflow 不够（分支爆炸/无法处理未预见输入）→ 为什么纯 Agent 也不行（可靠性）→ 最终形态（混合：Workflow 骨架+Agent 节点）与验证数据。

- 用真实 case 说明"未预见的输入路径"（Workflow 枚举不完）
- 承认自主性的代价并给护栏（预算/白名单/人审）
- 混合架构的具体切分线（哪些节点给了模型决策权，标准是什么）

**解析：**
- 这是对 Agent 项目最有杀伤力的问题：自主性的必要性论证
- 是否理解生产环境对确定性的偏好


### ProjectAgent-001-002 | ★★★★☆

Agent 的工具集是怎么设计的？工具质量怎么保证？

**答案：**
工具清单与职责划分（粒度：粗 vs 细的权衡）→ Schema 与描述规范（何时该用/参数约束/返回格式）→ 质量保障（工具单测、模拟环境、决策准确率评测）→ 权限与安全。

- 工具粒度决策案例："查询订单"拆成按单号/按用户两个工具而非一个大而全参数（描述更聚焦，选对率高）
- 描述规范：写清"何时用/何时不该用/返回什么"，并用错误调用案例迭代
- 高危工具的护栏（只读账号/白名单/人审）

**解析：**
- 工具设计是 Agent 效果的第一杠杆（描述/Schema/粒度）是否有认知
- 工具的安全与权限收敛

### ProjectAgent-001-005 | ★★★★☆

### ProjectAgent-001-006 | ★★★★☆

项目里工具调用的整体链路是怎么设计的？

### ProjectAgent-001-011 | ★★★★☆

接入 MCP 带来了什么？有什么坑？

**答案：**
接入动机（生态复用 M×N→M+N）→ 实际接入清单（哪些 Server）与收益 → 踩坑（Server 质量参差、鉴权、描述质量、传输选型）→ 治理（准入审核、工具命名冲突、描述二次加工）。

- 准入治理：第三方 Server 的权限声明审查、工具描述质量不满足要求时的包装层

**解析：**
- 对协议价值的真实评估（复用生态 vs 自建）而非跟风
- 落地细节（传输方式/鉴权/工具质量参差）


### ProjectAgent-001-012 | ★★★★☆

工具调用的安全审计是怎么做的？

**答案：**
权限模型（会话绑定用户身份、工具按角色收敛）→ 分级执行（读自动/写确认/高危 dry-run）→ 审计日志（参数/结果摘要/身份/会话，不可篡改留存）→ 风控（频控/异常模式检测）。

- 明确"工具执行时使用的是用户身份而非系统身份"（防 Agent 越权）
- 审计字段清单与留存策略（合规口径）
- 异常行为检测（如单会话高频敏感调用告警）

**解析：**
- 信任边界认知（模型不是权限主体）
- 审计的可追溯与合规属性


### ProjectAgent-001-013 | ★★★★☆

公司内部要不要自建 MCP Server？成本收益怎么算

**答案：**
收益（复用：M 个 Host 免重复对接 N 个内部系统；治理：统一鉴权审计收口）→ 成本（开发维护、鉴权打通、版本治理）→ 决策树（内部系统对接多个 AI 应用→建；只有单一 Agent 消费→普通工具函数即可）→ 演进路径（先内部工具注册表，跨应用复用需求出现再 MCP 化）。

**解析：**
技术选型的经济账；对 MCP 生态定位的清醒认知。
