# 复核与交付报告

交付前逐项回答，不得跳项；报告以文件形式存于本包目录（`交付报告_v3.md`）并同步要点给用户。

## 一、根因证据链复核

- Phase 0 探针数据是否在案：三点以上 Δ 数值 + 拟合结论（S′−S / O′−O）？
- 修复后同点位 Δ 复测 ≈ 0？
- “外层缩放是必要条件”的对照实验结论（若执行）是否记录？

## 二、架构复核（对照 02 冻结契约）

- Reader 是否只剩一条 canonical→screen 变换？逐层列出每个 transform 的来源与数值示例（z、offset、镜像层 position/transform）。
- Canvas 之上是否零祖先变换？
- contentSize 是否 display 单位？空 drawing / 有笔迹 / drawing 异步装载后滚动范围均正确？
- 属性所有权表是否被遵守（无第二个写入者）？
- hitTest 基准注释是否在位？

## 三、数据兼容复核

- PKDrawing 点坐标未被乘除/平移；历史笔迹真机对齐通过（10 号 A 项）。
- `node_id`、`ink_revision`、`blob_sha256`、`pkdrawing-v1`、outbox 语义全部不变。
- hover / 滚动零 ink 副作用。

## 四、测试与流程复核

- 07 纯逻辑单测：新增 N 项 + 既有 21 项全绿（附命令与计数）。
- 08 hosted 冒烟：全链路不崩 + 视口不变量断言全绿。
- 09 离线复现装置：脚本入库，手工端到端路径验证记录。
- 10 真机清单：A–D 逐项证据齐全。
- `git diff --check` 干净；白名单外的文件零改动（`git diff --stat 9866df4..HEAD` 核对）。
