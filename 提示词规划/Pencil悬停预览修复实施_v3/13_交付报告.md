## 一、两个根因与修复

### Bug 1：Pencil 近屏实时渲染错位（原始问题）
- 根因（Phase 0 实证）：旧架构外层 UIScrollView ×1.98 缩放包住 `zoomScale=1` 的 PKCanvasView——实时渲染路径（悬停预览+书写中墨迹）与提交路径基准分裂；Δ 双轴符号反转、y 轴拟合 S′≈2.026（残差 ±4.7pt）。证据见 `12_Phase0取证报告.md`。
- 修复：**单一显示变换架构**——PKCanvasView 成为唯一滚动/缩放 owner（`zoomScale=适宽比`，其上无任何祖先变换），正文降级为非交互镜像层（`anchor .zero + position −offset + scale z`），四者（正文/提交笔迹/实时墨迹/悬停预览）共享 `screen(P)=P·z−offset`。
- 附带修正：`contentSize` 用 display 单位（canonical×z）；hitTest 只约束 Pencil 触点且基准只除 zoomScale；Reader 内部纯 frame 布局（子树零约束，防 autolayout 回写打架）。

### Bug 2：双击节点即卡死（暂存版与 v3 初版的共同回归）
- 根因（进程采样实证）：`updateUIViewController → pencil.apply() → 无条件写 @Published isEraser（同值也触发 objectWillChange）→ @StateObject 重渲染 → updateUIViewController → ∞`，主线程 99% CPU。
- 修复：`apply` 仅在 `self.isEraser != isEraser` 时写入；回归测试 `testApplyWithSameValueDoesNotPublish` 钉死。
- 无头复现装置：`-uiTestOpenReaderNode <id|title>`（DEBUG launch argument）。
