# 学习心理学底座

整套设计并不依赖单一学习理论，而是组合几个互补机制。

## 1. Retrieval Practice｜主动检索

真正长期有价值的复习不是“再看一遍”，而是：

> 在没有材料辅助的情况下重新从长期记忆中生成答案。

因此：

- Knowledge 复习要求短解释；
- Algorithm 复习要求局部生成代码/结构；
- Project 复习要求重新生成工程判断。

## 2. Spacing｜分散学习

一次学习到当前会，不追求当天过度熟练。

更重要的是：

> 未来不同日期重新检索。

这也是 Learning Verified 与 Long-term Stable 分离的原因。

## 3. Worked Examples

完全陌生时，直接空白解决复杂问题可能浪费大量认知资源在无方向搜索上。

因此允许：

- 示例；
- 骨架；
- 部分完成；
- 解释；
- Worked Example。

但随着已有知识增长，支架应逐渐撤除。

## 4. Guidance Fading / Expertise Reversal

对 novice 有帮助的详细教学，对熟练者可能成为冗余。

因此教学量必须根据真实表现动态调整。

这直接支持：

- G1～G6；
- Algorithm Skill Blocks；
- Repair；
- 自动收缩教学内容。

## 5. Mastery Learning

一个内容只有达到当前学习标准后，才离开 Learning。

失败：

> corrective activity → retest

成功：

> Learning Verified

但这仍不等于长期掌握。

## 6. Interleaving

陌生 schema 初建时允许局部成块。

知识块稳定后主动切换领域：

```text
MySQL
→ JUC
→ OS
→ RAG
→ 回 MySQL
```

避免长期依赖单一上下文。

## 7. Transfer

同一个概念只重复原题，会逐渐变成记住 prompt。

因此验证优先采用：

> 相同底层知识 + 不同表面实例。

## 8. Flow

系统应尽量创造：

- 清晰当前任务；
- 即时但不过度的反馈；
- 挑战与当前能力匹配；
- 减少自我评分；
- 减少模式选择；
- 减少时间催促。

用户注意力应落在内容，而不是“我表现得怎么样”。
