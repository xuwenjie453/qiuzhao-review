# 完整生命周期示例

以：

> MySQL 的 Gap Lock 是什么？

为例。

## Learning

### Step 1
真人题冷启动。

用户回答：

> 大概是锁一个范围，用来防止幻读，Next-Key和它差不多。

### Step 2
AI诊断：

- 核心概念部分会；
- 锁定对象含混；
- Gap / Next-Key 混淆；
- 幻读关系有概念。

### Step 3
默认 G2：

- Record Lock
- Gap Lock
- Next-Key Lock
- Range Query
- Phantom

### Step 4
关闭知识块，重答原题。

### Step 5
验证：
- 辨析题；
- 机制题；
- 一个简单场景题。

### Step 6
如果 Next-Key 仍错误：

> Repair Block

### Step 7
迁移通过：

`LEARNING_VERIFIED`

## Review Probe Compilation

Learning Engine 不把原题加入 Review。

生成 Capsule：

```text
target = MySQL/GapLock

must_retrieve:
- 锁定对象
- 作用
- 与 Next-Key 基本边界

allowed_probe:
- Explain
- Contrast
```

## 未来复习

Scheduler 根据日期和 Goal 判断该 Capsule 值得复习。

Review Engine 给：

> Gap Lock 锁的是什么？它和 Next-Key Lock 的核心区别是什么？

用户答清楚：

`REVIEW_SUCCESS`

立即结束。

未来不同日期再用另一 Probe。

## 半年后

历史事件还在。

R 降低。

如果 Reactivation Goal 生效：

系统再次用一个短 Probe 测。

成功：
快速恢复 Stability。

失败：
Repair / Relearning。

整个生命周期无需重复原始长题。
