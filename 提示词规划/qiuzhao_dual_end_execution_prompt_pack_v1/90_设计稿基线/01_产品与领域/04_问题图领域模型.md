# 问题图领域模型

> 本文定义 QuestionGraph 的核心对象。自“问题图继承”架构更新起，`nodes.graph_id` 的语义明确为 **owner graph**，而“节点在哪些图中可见”由 owned membership + graph inheritance 共同决定。详细继承契约见 `05_问题图继承与共享解释节点.md`。

## 1. QuestionRef

```json
{
  "source": "QUESTION_BANK | REVIEW_CAPSULE",
  "question_key": "qb:Redis-xxx-001",
  "source_id": "Redis-xxx-001",
  "probe_key": null,
  "body_sha256": "..."
}
```

`question_key` 必须稳定。

- Question Bank：`qb:<question_id>`。
- Review：`capsule:<capsule_id>:<probe_key>`。
- Review Capsule 本体不是 graph identity；一次物化出的具体 probe 才对应一个 QuestionGraph。

CENTER 的正文以第一次创建 graph 时的 source snapshot 为准；若上游题干未来变化，v1 不隐式覆盖已有 graph body，而是记录 `source_body_changed` 供诊断。

## 2. QuestionGraph

```text
QuestionGraph
- graph_id: UUID/string stable
- question_key: unique
- question_source: QUESTION_BANK | REVIEW_CAPSULE
- source_id
- probe_key nullable
- graph_revision: integer monotonic
- center_node_id: unique
- created_at
- updated_at
```

每个 graph 恰好拥有一个 CENTER。CENTER 不参与继承。

QuestionGraph 的**有效视图（effective graph view）**定义为：

```text
EffectiveNodes(G)
= OwnedVisibleNodes(G)
+ InheritedExplanationNodes(G)
```

因此“节点属于哪个图”和“节点在哪个图可见”不再等价。

## 3. GraphNode

```text
GraphNode
- node_id
- graph_id              # storage column; semantic = owner_graph_id
- kind: CENTER | EXPLANATION | TEMPORARY
- title
- body_markdown
- body_sha256
- round_id nullable
- node_revision
- deleted_at nullable
- created_at
- created_by: AGENT | SYSTEM
- origin_turn_ref nullable
```

### 3.1 Ownership

`nodes.graph_id` 永远表示该节点的 **canonical owner graph**。

- OWN 节点：owner graph 与当前 view graph 相同。
- INHERITED 节点：owner graph 与当前 view graph 不同，但通过 `graph_inheritance` 对当前图可见。
- inherited node 不复制，不产生新的 `node_id`。

### 3.2 硬不变量

- `CENTER.round_id IS NULL`
- `EXPLANATION.round_id IS NULL`
- `TEMPORARY.round_id IS NOT NULL`
- 每 graph 恰好 1 个非 deleted、owned CENTER
- CENTER 删除命令永远拒绝
- body 只可在 INSERT 时写，后续 UPDATE body 由 DB trigger/command layer 拒绝
- title 可编辑
- CENTER 永不继承
- TEMPORARY 永不继承
- 仅 EXPLANATION 可通过继承进入另一个 graph 的 effective view

## 4. Layout

每个 canonical node 一个 presentation record：

```text
node_id
x_norm, y_norm         # 0..1 逻辑坐标，不直接保存像素
layout_revision
pinned_by_user
updated_at
```

Layout 是 node-scoped，而不是 graph-scoped。若 EXPLANATION 被多个 graph 共享，则其 layout 也共享：从任一可见 graph 拖动该节点，所有引用同一 `node_id` 的 graph 都看到相同 canonical layout。

使用归一化坐标保证 iPad 横竖屏/不同尺寸恢复位置。拖动时先本地 durable，再同步。

## 5. Ink

```text
node_id
ink_revision
format = PENCILKIT_PKDRAWING_V1
blob_sha256
blob
updated_at
```

Ink 同样是 canonical node-scoped。共享 EXPLANATION 在父图和所有继承图中读取、写入同一份 Ink。

Ink 不属于 graph_revision。原因：书写是高频数据，不能每一笔让图结构 revision 抖动。Ink 通过 `node_id + ink_revision` 单独保证顺序与幂等。

## 6. Relation 边界

QuestionGraph 仍不引入任意知识 edge 表。

- owned child 在视觉上可连向当前 graph CENTER；
- inherited EXPLANATION 在 child graph 中也可视觉连向 child CENTER；
- 该视觉线只是 view relation，不改变 node owner，不表示知识依赖；
- graph inheritance 是 graph-to-graph relation，和节点视觉连线是两类不同关系。

## 7. 版本说明

旧基线中“所有非 CENTER 节点都属于同一 CENTER”的表述只适用于无继承 graph。升级后应解释为：

> 所有 owned 非 CENTER 节点属于本 graph；继承图还可以直接显示其他 graph 拥有的 EXPLANATION，但这些节点的 canonical owner 不发生改变。
