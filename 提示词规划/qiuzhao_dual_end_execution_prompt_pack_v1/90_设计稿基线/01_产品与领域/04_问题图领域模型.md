# 问题图领域模型

## 1. QuestionRef

```json
{
  "source": "QUESTION_BANK | REVIEW_CAPSULE",
  "question_key": "qb:Redis-xxx-001",
  "source_id": "Redis-xxx-001",
  "probe_key": null,
  "body_sha256": "..."
}
```

`question_key` 必须稳定。CENTER 的正文以第一次创建 graph 时的 source snapshot 为准；若上游题干未来变化，v1 不隐式覆盖已有 graph body，而是记录 `source_body_changed` 供诊断。

## 2. QuestionGraph

```text
QuestionGraph
- graph_id: UUID/string stable
- question_key: unique
- graph_revision: integer monotonic
- center_node_id: unique
- created_at
- updated_at
```

v1 关系语义固定为：所有非 CENTER 节点都属于同一 CENTER。可以画线连接中心，但不存 arbitrary edge 表；避免凭空引入用户没有要求的知识关系。

## 3. GraphNode

```text
GraphNode
- node_id
- graph_id
- kind: CENTER | EXPLANATION | TEMPORARY
- title
- body_markdown
- body_sha256
- round_id nullable
- node_revision
- deleted_at nullable
- created_at
- created_by: AGENT | SYSTEM
- origin_turn_ref nullable
```

硬不变量：

- `CENTER.round_id IS NULL`
- `EXPLANATION.round_id IS NULL`
- `TEMPORARY.round_id IS NOT NULL`
- 每 graph 恰好 1 个非 deleted CENTER
- CENTER 删除命令永远拒绝
- body 只可在 INSERT 时写，后续 UPDATE body 由 DB trigger/command layer 拒绝
- title 可编辑

## 4. Layout

每个 node 一个 presentation record：

```text
node_id
x_norm, y_norm         # 0..1 逻辑坐标，不直接保存像素
layout_revision
updated_at
```

使用归一化坐标保证 iPad 横竖屏/不同尺寸恢复位置。拖动时先本地更新，再同步。

## 5. Ink

```text
node_id
ink_revision
format = PENCILKIT_PKDRAWING_V1
blob_sha256
blob
updated_at
```

Ink 不属于 graph_revision。原因：书写是高频数据，不能每一笔让图结构 revision 抖动。
