# 问题身份与轮次生命周期

## 1. 稳定问题身份

### 试题库

`question_key = "qb:" + permanent_question_id`

必须使用题库永久题号，而不是题干 hash；题干 hash 仅用于检测上游内容漂移。

### 复习胶囊

设计要求 `question_key = "capsule:" + capsule_id + ":" + probe_key`。

如果当前 Review Engine 没有稳定 `probe_key`，新增一个**只用于双端身份**的稳定字段。禁止把每次生成的自然语言题干 hash 当唯一身份，否则同一胶囊每轮措辞变化会产生无限新图。

## 2. Round

每次 Agent 开始围绕问题讨论：

```text
question.open
  -> close previous active round if any
  -> create round_id UUID
  -> mark active
  -> build visible graph = CENTER + persistent + temp(round_id only)
  -> push snapshot
```

### close 触发条件

- Agent 明确切换到另一道问题；
- 本轮学习任务完成；
- review probe 完成；
- 用户显式结束当前题。

不要用沉默超时判断 Round 结束；这与现有系统“时间只用于调度，不用沉默推断用户状态”的哲学一致。

## 3. Temporary cleanup

`question.close(round_id)`：

1. round.status = CLOSED；
2. 当前 round 的 TEMPORARY `expired_at = now`；
3. graph_revision++；
4. 对在线 iPad 发 patch/remove；
5. 新 round snapshot 过滤所有旧 temporary。

崩溃恢复时，如果旧 round 没被正常 close：下一次 `question.open` 同图或其他图前，daemon 先把所有 `ACTIVE` 但不等于新 round 的 round 标记 `INTERRUPTED`，其 temporary 全部过期。因此“下次推送不得出现上次临时节点”仍成立。
