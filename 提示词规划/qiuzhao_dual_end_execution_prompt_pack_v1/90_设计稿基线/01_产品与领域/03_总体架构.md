# 总体架构

## 1. 逻辑组件

```mermaid
flowchart LR
  U[用户] <--> A[ZCode/Codex Agent]

  I --> C[(iPad Local SQLite)]
```

## 2. 权威边界

### 现有学习领域

权威仍属于原有 Python + SQLite：题库、Goal、调度、学习事件、review capsule。

### 新双端领域

Mac `QuestionGraph Store` 是以下数据的 canonical merge point：

- graph identity；
- node existence/tombstone；
- node immutable body；
- title；
- graph layout；
- round lifecycle；
- iPad Ink 备份；
- sync journal。

iPad 本地库是交互侧 durable cache / outbox，不取代 Mac canonical authority。

## 3. 主流程

```mermaid
sequenceDiagram
  participant U as User
  participant A as Agent
  participant D as Mac Daemon
  participant I as iPad

  U->>A: 开始学习 / Agent 调度到问题
  A->>D: question.open(question_key, body, ai_title)
  D->>D: ensure graph + new round
  D->>I: GRAPH_SNAPSHOT(active=true)
  I->>I: durable apply + show topology

  U->>A: 追问
  A-->>U: Markdown 解释
  U->>A: “把刚才这段加入问题图”
  A->>D: graph.node.add(EXPLANATION, exact_markdown, ai_title)
  D->>I: GRAPH_PATCH(add node)

  U->>I: 移动节点 / 改标题 / 手写
  I->>I: local durable
  I->>D: CLIENT_COMMAND / INK_PUT
  D->>D: validate + durable
  D-->>I: ACK + patch if needed

  U->>A: 切换下一题
  A->>D: question.close(round_id)
  D->>D: expire TEMPORARY
  A->>D: question.open(next question)
  D->>I: new snapshot
```

## 4. 为什么不让 Daemon 监听聊天窗口

ZCode/Codex 等 Agent 宿主没有统一可靠的外部 transcript hook。抓窗口/日志会造成宿主耦合和隐私风险。当前 Agent 已经执行 Runtime Prompt，因此最可靠的集成点是**Agent 显式调用稳定 CLI/localhost API**。
