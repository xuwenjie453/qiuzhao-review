# Mac 双端 Store

## 1. 新库

`系统数据/dual-end/state/dual-end.db`

SQLite pragmas：

```sql
PRAGMA journal_mode=WAL;
PRAGMA synchronous=FULL;
PRAGMA foreign_keys=ON;
PRAGMA busy_timeout=5000;
```

不把新表塞进 `scheduler.sqlite3`，原因：双端 presentation/sync 高频状态不属于学习调度领域。

## 2. 事务边界

每个 command 一个 SQLite transaction：

1. dedup lookup；
2. load current revisions；
3. validate invariant；
4. mutate domain rows；
5. append sync_journal；
6. store command result；
7. COMMIT；
8. commit 后才向 WebSocket emit/ACK。

## 3. Body immutable

实现双保险：

- command API 无 `update_body`；
- SQLite trigger 阻止 UPDATE `body_markdown/body_sha256`。

## 4. Ink blob

v1 可直接用 SQLite BLOB；解释节点通常数量有限，部署简单且 transaction 一致。若真实使用后单库膨胀，再迁移为 content-addressed file，不在 v1 提前复杂化。

## 5. 数据保留

- tombstone node：永久保留元数据，避免旧 patch 复活；
- expired temporary：保留 metadata/body 用于诊断，但 snapshot 永远过滤；
- sync journal：可按 server_seq checkpoint 做压缩；至少保留最近 10k 条或 30 天；
- ink：deleted node 可保留，不主动 GC v1。
