# 迁移与兼容策略

## 1. 从当前 repo 升级

没有现有问题图数据，因此 v1 migration 是 additive：

- 创建 `DualEnd-Mac/`；
- 创建 `DualEnd-iPad/`；
- 首次 daemon start 创建 `系统数据/dual-end`；
- 原 SQLite 不做 destructive migration。

## 2. QuestionGraph lazy creation

不要批量为 2383 道题预生成 graph。第一次 `question.open` 时创建：

- graph；
- center node；
- default layout。

这样无无用数据和 AI 标题批处理成本。

## 3. 旧学习会话

双端上线前的历史 learning events 不反向生成 explanation nodes，因为用户没有做过“显式加入”的选择。自动回填会违反最核心用户约束。

## 4. 协议升级

Store schema 有 `schema_version`；wire 有 `v`。升级顺序：

1. daemon migration；
2. daemon 保持至少一个旧 client protocol 窗口（若需要）；
3. iPad upgrade；
4. 再删除旧协议。

v1 首发无需兼容不存在的 v0。
