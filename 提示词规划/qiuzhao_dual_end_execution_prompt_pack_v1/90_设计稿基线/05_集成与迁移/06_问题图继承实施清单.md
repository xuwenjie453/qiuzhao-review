# 问题图继承实施清单

> 本清单把 `05_问题图继承与共享解释节点.md` 拆成可直接执行的代码改造面与验收 Gate。实现时应按 Phase 顺序推进，避免先改 iPad UI、后补 canonical 语义。

## Phase A — 契约冻结

必须先完成：

- [ ] 确认 V1 只允许 `REVIEW_CAPSULE -> QUESTION_BANK` inheritance。
- [ ] inheritance kind 固定 `SHARED_EXPLANATIONS`。
- [ ] inherited kinds 仅 `EXPLANATION`。
- [ ] shared node mutation 为 write-through。
- [ ] layout/ink 均 node-scoped，不做 per-graph override。
- [ ] inherited delete 为 global delete，iPad 二次确认。
- [ ] existing Review graph 不猜 parent。
- [ ] Review Capsule 增加 `primary_source_question_id`。

## Phase B — Mac Store / Graph Core

### `DualEnd-Mac/src/store/state-db.mjs`

- [ ] `SCHEMA_VERSION` -> 2。
- [ ] 增加 schema migration runner，而不是只在空库 DDL 初始化。
- [ ] 新增 `graph_inheritance`。
- [ ] 加 parent index。
- [ ] 保证 v1 existing DB 无损升级。

### `DualEnd-Mac/src/graph/question-graph-service.mjs`

新增能力：

- [ ] `ensureInheritance(childGraphId,parentGraphId,kind)`。
- [ ] source type 验证。
- [ ] self/cycle guard。
- [ ] `parentGraphs(graphId)`。
- [ ] `effectiveNodes(graphId,roundId)`。
- [ ] `affectedGraphsForNode(nodeId)`。
- [ ] shared structural mutation revision fan-out。
- [ ] snapshot 返回 effective view，而不是 owner-only rows。
- [ ] inherited node command visibility validation。

保持：

- [ ] node body immutable。
- [ ] CENTER delete forbidden。
- [ ] rename node_revision CAS。
- [ ] move layout_revision CAS。
- [ ] ink revision sequence。
- [ ] command dedup。

### `DualEnd-Mac/src/daemon.mjs`

- [ ] `question.open` 支持 declarative `inherit_from`。
- [ ] 可选新增 `graph.inherit` command。
- [ ] shared node mutation 能向所有 affected graph 生成 revision/patch。
- [ ] active graph 至少实时收到 patch。
- [ ] inheritance 初次建立优先发 snapshot，降低 patch membership 复杂度。

## 建议实现顺序

```text
A 契约
-> B Mac canonical
-> C wire
-> D iPad store
-> E UI
-> F learning integration
-> G tests
-> H release
```

禁止反向先做 UI mock，再补共享 identity；否则极易形成“看起来继承、实际复制”的错误实现。
