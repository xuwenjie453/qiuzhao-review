# 自动信任与安全边界

## 1. 硬约束导致的取舍

用户要求“自动发现、自动连接、无需手动配对”。这排除了 reading-system 当前 6 位验证码式首次配对。

没有预共享账号/iCloud/二维码/验证码时，首次局域网发现无法同时做到“完全零交互”和“强人工确认对端身份”。因此 v1 明确采用：

> **个人可信 LAN 为信任边界 + 首次连接自动 TOFU（Trust On First Use）**。

## 2. TOFU

- daemon 有稳定 `daemon_id`；
- iPad 第一次成功协议 HELLO/WELCOME 后缓存 `preferred_daemon_id`；
- 后续优先该 daemon；
- daemon 可记录 `device_id` 用于诊断，但不弹批准框。

## 3. v1 不宣称的安全能力

- 不宣称抵抗同一恶意 LAN 上的主动 MITM；
- 不宣称公网安全；
- 不允许路由器端口映射作为支持用法。

## 4. 最小防护

- Local Control API 只绑定 loopback；
- WebSocket 消息严格 schema/size 限制；
- node body 单条例如 2 MiB 上限；Ink 单 snapshot 20 MiB 上限（可配置）；
- 不执行接收到的 Markdown HTML/script；
- 链接点击交给系统安全 URL handler；
- daemon 日志不记录完整 node body/ink。

如果未来要求 hostile-LAN 强安全，需要新增显式身份绑定机制；那将与“零人工配对”产生新的产品决策。
