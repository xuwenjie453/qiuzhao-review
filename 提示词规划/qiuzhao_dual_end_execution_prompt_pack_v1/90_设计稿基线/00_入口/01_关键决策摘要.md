# 关键决策摘要

| 编号 | 决策 | 理由 |
|---|---|---|
| D01 | 本次仅做双端扩展，不重构学习核心 | 用户明确“这一次只是做双端更新” |
| D02 | Question 是跨端最小业务中心 | 用户明确“一切交互围绕问题” |
| D03 | 每个 Question 对应稳定 QuestionGraph | 解释、布局、笔迹需跨轮次保留 |
| D04 | v1 图只有 CENTER→子节点的星型语义 | 需求只规定中心问题+解释；不擅自增加知识关系 |
| D05 | Persistent/Temporary 都必须由用户显式触发 | 系统不得自动选择解释入图 |
| D06 | 临时节点用 round_id 隔离，不靠内存临时对象 | 断网/重启可恢复，同时保证下一轮不出现 |
| D07 | Mac 新增独立 dual-end store | 不污染 scheduler / Knowledge / Algorithms / Projects 现有真源 |
| D08 | Bonjour + WebSocket | 与 reading-system 已验证结构一致；满足 LAN 零配置 |
| D09 | 去掉验证码配对，采用自动 TOFU/可信 LAN | 用户要求无手动配对；明确安全代价 |
| D10 | Mac 为 graph/content authority，iPad local-first | 保证断网可读写，又维持单一合并点 |
| D11 | Ink 独立 revision，不绑 graph revision | 高频笔迹不能导致整图 revision 冲突 |
| D12 | Node body immutable；title/layout 可变 | 与用户“正文不变、iPad 只改标题”完全一致 |
| D13 | Agent 生成初始标题 | 用户要求 AI 概括；避免 daemon 自带第二套模型 |
| D14 | iPad UI 用 SwiftUI + UIKit/PencilKit bridge | 图/UI 适合 SwiftUI；低延迟笔迹需原生 PencilKit |
| D15 | 阅读页使用单一滚动坐标系 | Markdown 与 Ink 必须永久像素对齐 |
| D16 | Snapshot/Patch + dedup + durable-before-ACK | 直接复用 reading-system 的可靠同步原则 |
