# 02 — 基线审计与不可破坏契约

在写任何代码之前，先验证并记录这些事实。若当前仓库已有等价机制，以现有机制为准；不要重复发明。

## 1. Mac canonical 不变量（MUST PRESERVE）

确认当前实现并保持：

- Mac `StateDb` / `QuestionGraphService` 是 QuestionGraph canonical source of truth。
- `CENTER`：每图唯一、永久、不可删除。
- `EXPLANATION`：永久，`round_id = NULL`。
- `TEMPORARY`：绑定 ACTIVE round；close/interrupted 后过期且不复活。
- `body_markdown` immutable；API 与 DB trigger 的双保险不得弱化。
- rename/move/delete 的 CAS 与 node/layout revision 语义不得改变。
- canonical change 对 graph revision 的现有递增规则不得被本功能绕过。
- command dedup / replay-safe journal / durable-before-emit 语义不得破坏。
- `QUESTION_BANK`、`REVIEW_CAPSULE`、`USER_AUTHORED` 图身份规则不得改变。
- Review → QuestionBank `SHARED_EXPLANATIONS` inheritance 不得被重新设计。

## 2. iPad 不变量（MUST PRESERVE）

- iPad cache/outbox 先 durable 后发送的规则不变。
- iPad 不能改 node body。
- 节点 drag 仍然是 canonical layout mutation；pan 不是。
- tap / double tap / drag / Pencil ink 现有语义不得因 pan 或 hierarchy 丢失。
- 断线后 cached snapshot 仍可展示。

## 3. Runtime Agent 不变量

根据 RuntimePrompt 21：

- 普通解释**不自动入图**；只有用户明确要求加入时才调用 `graph.add-node`。
- 普通加入解释时，`body_markdown` 仍是用户指中的 assistant 原解释原文。
- daemon 不在线时不得伪造“已加入”，但学习会话继续。
- inherited Explanation 由 GraphService effective view 提供，不由 Agent 手工复制。
- 自拟图规则、Review inheritance、独立复习调度保持不变。

本功能唯一新增的 Runtime 例外是：

> 用户明确要求“解析/抽取某个已经存在的节点内容”为子节点时，Agent 可以基于该父节点正文重新组织目标主题，并将新 EXPLANATION 的 `parent_node_id` 指向父节点。

这个例外不能扩展到普通 add-node。

## 5. 变更边界

### Canvas Pan 允许修改

主要只应在：

```text
DualEnd-iPad/QiuZhaoReader/Topology/
DualEnd-iPad/QiuZhaoReaderTests/
```

若为了纯几何 helper 在 iPad 本地新增小文件可以接受。

Canvas Pan **不得要求修改**：

```text
DualEnd-Mac/
Mac SQLite schema
sync wire protocol
ClientStore canonical cache schema
```

### Parent Node 允许修改

预计集中在：

```text
DualEnd-Mac/src/store/state-db.mjs
DualEnd-Mac/src/graph/question-graph-service.mjs
DualEnd-Mac/src/daemon.mjs
DualEnd-Mac/test/

DualEnd-iPad/QiuZhaoReader/Store/ClientStore.swift
DualEnd-iPad/QiuZhaoReader/Topology/QuestionGraphView.swift
DualEnd-iPad/QiuZhaoReaderTests/
```

### Runtime Parse 允许修改

优先只改：

```text
提示词规划/秋招智能学习与复习体系_RuntimePrompt_V1/21_双端问题图与iPad协作协议.md
```

只有现有自然语言控制协议确实需要增加命令映射时，才最小修改 `15-自然语言控制协议.md`。不要复制一套新 RuntimePrompt。

## 6. 若发现设计冲突

不要立刻扩张架构。按优先级处理：

1. 保住 canonical / sync / durable 不变量；
2. 保住本包明确用户语义；
3. 用最小 additive migration / optional field 解决兼容；
4. 只有确实无法满足时才在最终报告中指出阻塞，而不是自行引入大规模新模型。
