# 07 — 测试、兼容性与最终审计 Prompt

这是完成门槛。不要只证明“新代码能编译”，还要证明旧图、旧 cache、旧 command、inheritance 与 gesture 没被破坏。

## 1. 先确定可执行测试命令

不要猜。先检查：

- `DualEnd-Mac/package.json` / test scripts；
- iPad Xcode project / test target；
- 当前环境是否有 Node 版本、Xcode、Simulator。

然后执行所有当前环境可运行的相关测试。

建议至少：

```text
Mac node:test / package test（以仓库实际 script 为准）
现有 DualEnd-Mac tests 全量
新增 hierarchy/migration tests

git diff --check
```

如果 macOS + Xcode 可用，再执行 iPad build/test。若当前执行环境没有 Xcode：

- 不要声称 iPad tests passed；
- 运行能运行的纯 Swift/静态检查（若可行）；
- 检查 Xcode file synchronization 机制，确认新 test 文件是否自动进 target；
- 在最终报告明确列出未运行项。

## 2. Schema compatibility matrix

### Fresh DB

验证：

- 新 schema version 正确；
- `nodes.parent_node_id` 存在；
- CENTER null；
- 新 non-center 的 parent 按规则写入；
- integrity / foreign_key_check 为 ok/0 violations。

### Existing v3 DB

构造/复制一个旧 schema fixture，至少含：

```text
Graph
CENTER
EXPLANATION A
TEMPORARY/历史节点（如迁移 fixture 合理）
layout
ink（至少一个引用 node 的 row）
```

升级后验证：

- node ids 不变；
- graph ids 不变；
- layout/ink 不丢；
- CENTER parent=NULL；
- 旧 non-center parent=对应 graph CENTER；
- immutable trigger 仍生效；
- foreign keys 无 violations。

不要只测试空 DB migration。

## 3. Wire compatibility matrix

### Old producer → New iPad

old snapshot node 无 `parent_node_id`：

```text
decode success
non-center presentation parent = current CENTER
```

### New producer → New iPad

snapshot/ADD_NODE patch 有 parent：

```text
explicit parent preserved through cache/render
```

### New server → Old conceptual client

因为新增字段是 additive optional JSON，确认没有改变旧必需字段/命令名。不要主动破坏 old payload shape。

## 4. Parent validation matrix

全部测试：

| child kind | parent | 预期 |
|---|---|---|
| EXPLANATION | omitted | CENTER |
| EXPLANATION | CENTER same graph | success |
| EXPLANATION | EXPLANATION same graph | success |
| EXPLANATION | missing id | reject |
| EXPLANATION | deleted node | reject |
| EXPLANATION | TEMPORARY | reject |
| EXPLANATION | node in other graph | reject |
| EXPLANATION | inherited node owned by ancestor graph | reject |
| TEMPORARY | omitted | CENTER |
| TEMPORARY | explicit custom parent | reject |

明确非法 parent 时不得静默变 CENTER。

## 5. Hierarchy render matrix

验证这些 snapshot：

### 旧星形图

```text
CENTER
├── A(parent nil / legacy)
└── B(parent nil / legacy)
```

显示与旧版本一致。

### 多级

```text
CENTER
└── A
    ├── B
    │   └── D
    └── C
```

每条 link start/end 正确。

### parent 被删除/不可见

```text
A absent
B.parent=A
```

B 仍显示；link presentation fallback CENTER；canonical B.parent 仍=A。

### inheritance

- inherited child parent=inherited explanation 且二者都 visible → 保留 inherited hierarchy；
- inherited explanation parent=source CENTER（不 visible）→ 当前 Review CENTER fallback；
- Review OWN child 不能创建在 inherited parent 下。

## 6. Canvas Pan matrix

### Gesture ownership

| start | move path | 预期 |
|---|---|---|
| blank | 穿过 node | 始终 pan |
| normal node | 移出 node | 始终 node drag |
| CENTER | 移到 blank | CENTER 不动，canvas 也不 pan |
| blank small tap | 无明显移动 | background tap 仍工作 |

### Transform

- node/link 一起 offset；
- hit rect 跟随视觉 node；
- 画布先 pan O，再拖 node Δ：canonical normalized delta 与不 pan 时相同；
- 不发生 double-offset link；
- graph switch reset viewport offset；
- node/snapshot/viewport size 变化后 offset re-clamp。

### Canonical side effects

纯 pan 期间必须确认：

```text
0 MOVE_NODE
0 Mac mutation
0 graph_revision increment
0 layout_revision increment
```

## 7. Runtime behavior matrix

验证更新后的 Prompt 文本不会混淆：

1. 普通回答 → 不自动加节点；
2. “把刚才解释加入图” → 原 assistant body，parent default CENTER；
3. “把刚才解释挂到 X 下” → 原 assistant body + parent=X；
4. “解析 X，把 Y 抽出来” → 可重组 X body + parent=X；
5. daemon failure → 不伪造创建成功；
6. 父节点内容不足以支持目标主题 → 不从常识偷偷补齐并冒充“抽取自父节点”。

## 9. Diff 审计

最终执行并人工检查：

```text
git diff --check
```

并搜索确认没有误引入：

```text
PARSED_NODE
CHILD_EXPLANATION
CREATE TABLE edges
node.reparent
```

确认 Canvas Pan diff 没有触碰 Mac/sync schema（除非同一分支同时实现 Parent Node，而改动能明确归因于 Parent 功能）。

检查所有 SQL INSERT column/value 数量；检查 optional parent 在 snapshot 与 patch 两条路径都存在。

## 10. 最终报告格式（必须按此输出）

实现完成后给用户一份简洁但可审计的报告：

### 实现内容

分别说明：

- Canvas Pan；
- Parent Node canonical + sync + cache + render；
- Runtime 解析节点语义。

### 关键兼容策略

说明：

- schema migration；
- legacy parent fallback；
- deleted/inherited parent presentation fallback；
- pan local-only。

### 测试

列出**实际运行**的命令与结果。

### 未运行 / 剩余风险

例如：

```text
当前环境无 Xcode，因此未运行 Simulator gesture tests；已完成 Swift diff/static review 与纯逻辑 tests，但仍需在 macOS/Xcode 环境验证实际手势竞争。
```

### 变更文件 / commits

列出主要文件与 commit SHA。

不要说“全部测试通过”，除非确实运行了相应平台的全部测试。

## 11. Definition of Done

只有同时满足以下条件才算 Done：

- [ ] blank canvas pan 达到用户语义且无 canonical side effects；
- [ ] pan 后 node drag canonical 坐标正确；
- [ ] parent schema 可从旧 DB 安全迁移；
- [ ] default CENTER + explicit parent validation 正确；
- [ ] snapshot + ADD_NODE patch 都携带 parent；
- [ ] iPad cache 重启后 parent 保留；
- [ ] parent-child links 正确，缺 parent fallback 不写回；
- [ ] inheritance 场景不产生跨图 OWN parent；
- [ ] Runtime 21 明确区分普通 add-node 与 parse exception；
- [ ] 未新增节点 kind/通用 edges/reparent；
- [ ] 旧核心 tests 无功能性回归；
- [ ] 测试限制被如实披露。
