# 实现依据与外部规范

本文件说明若干工程选择的外部技术依据，但系统不机械照搬外部产品。

## SQLite ATTACH DATABASE
多个物理 SQLite 数据库可在一个连接中临时 ATTACH，并用 `schema-name.table-name` 跨库读取。

实现注意：
- 不因为跨库查询而合并所有数据库；
- 尽量让写入保持单库事务；
- 多 attached DB 的跨库事务原子性与 journal mode 等条件有关。

官方：
https://www.sqlite.org/lang_attach.html

## SQLite FTS5
资料库关键词全文检索使用 FTS5，适合 AQS、Next-Key Lock、volatile、PagedAttention 等技术精确术语。

官方：
https://www.sqlite.org/fts5.html

## SQLite Integrity
数据库 QA 同时执行：

```sql
PRAGMA integrity_check;
PRAGMA foreign_key_check;
```

因为 `integrity_check` 不负责发现外键约束错误。

官方：
https://www.sqlite.org/pragma.html

## FSRS-inspired Memory Model
使用：
- Difficulty
- Stability
- Retrievability

FSRS 当前算法基于 D/S/R 记忆状态模型；Stability 对应 R=90% 的时间尺度；FSRS-6 使用可训练遗忘曲线。

参考：
https://github.com/open-spaced-repetition/awesome-fsrs/wiki/The-Algorithm

本系统只借用记忆建模思想；Temporal Scheduler 不等同于 Anki due queue。

## Desired Retention
目标保持率越高通常意味着更多复习成本。本系统不使用全局固定 retention，而由 Goal、Importance、日期与引擎类型动态调整。

Anki Manual：
https://docs.ankiweb.net/deck-options
